# 经验与踩坑台账

## 2026-11-07 下载引擎 once 兜底队列死源空转导致永久 0 B/s 卡死

### 现象
GUI 安装 `26.2-NeoForge 26.2.0.93`，installer 主文件下到 48% 后速度 0 B/s、剩余 1 文件，长期挂起不报错。

### 判断过程
1. 真机同栈（.NET HttpClient）双源探测：
   - 镜像 `bmclapi2.bangbang93.com/maven/.../neoforge-26.2.0.93-installer.jar` → **403 Forbidden（410ms 稳定返回）**；
   - 官方 `maven.neoforged.net/releases/...` → **12s 连接超时不可达**。
2. 通读 `PCL.Download/DownloadFileTask.cs` 失败闭环，定位代码侧永久卡死路径：
   - 整体失败重试（`!_retried` 分支）把所有源（含已 `IsFailed` 的死源）塞进 `_onceSources`，**但未重置 `IsFailed`/计数**；
   - once 模式只 `Peek()` 队首，队列**从无 `Dequeue`**，也不跳过 `IsFailed` 源；
   - 结果：死源留在队首反复 403/超时 → `Reset` → 调度器再 Peek 同一死源，既不换源也不 `Fail`，空转永久挂起；
   - 兜底看门狗 `ForceRestart` 只 Reset 重下、不限次数，可能叠加成「重启-失败-重启」循环。

### 结论（已落地修复）
- `PeekOnceSource()`：once 选源跳过并出队 `IsFailed` 源，队列耗尽返回 null。
- `TryBeginChunk` once 分支：耗尽且无多线程源时直接 `Fail`，不再空转。
- 整体重试前重置每个源的 `IsFailed/FailCount/ZeroProgressFails/Error`，让重试真正重新评估。
- once 单线程源失败即出队换下一个，失败源不留队首。
- `ForceRestart` 累计上限（3 次），超过即 `Fail`，杜绝兜底重启无限循环。
- 回归：引擎 24 用例 + 全量 296 测试通过；新增 `Mirror403AndOfficialHang_FailsVisiblyNotStuck` 复现用例（403 镜像 + 挂起官方，断言 15s 内明确失败而非挂起）。

### 适用边界（硬环境限制，代码绕不开）
- 本次修复消除的是**永久卡死/不报错**；它**不能让不可达源变可达**。
- 镜像 403 属 WAF 按 TLS JA3 指纹拦 .NET 栈（UA/Range/Referer/HTTP 版本均无法绕开，curl 同链路 200）；官方 maven 在本网络被墙。这两条是网络/环境阻塞，需换网络、代理或提供可达的第三 maven 镜像才能真正下载成功。
- 修复后该场景表现为**快速明确失败并上抛异常**，而不是挂 0 B/s。

### 环境前置注意
- 本机 `git`、`powershell`（旧名）不在 PATH，仅 `pwsh` 与 `C:\Program Files\dotnet\dotnet.exe` 可用。
- `pcl-next.vbproj` 的 `PclBuildInfo` target 调 `powershell` 生成 `obj\<Config>\PclBuildInfo.g.vb`；该命令失败时 g.vb 缺失 → `BC30451: 未声明 PclBuildInfoGenerated`。此为环境前置缺失，与引擎改动无关。手动按 `scripts/Get-BuildSmallVersion.ps1` 退化模板（nogit/0.00）在对应 `obj\Debug` 目录补一份 g.vb 即可编过（生成物不入库）。
