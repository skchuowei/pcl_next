# Alpha 阶段缺陷扫描（2026-11-14）

> 范围：`PCL_NEXT_Windows_slush` 工作树，分支 `alpha-Windows`（基线 `10d3dad`）。
> 方法：基线编译 → 逐条复核 dev.6 遗留候选 → 静态扫描迁移痕迹 → 真实启动冒烟（读日志）。
> 本轮只做缺陷修复与质量加固，不引入新功能（符合 alpha 阶段「只收 bug」的裁决）。

## 一、结论摘要

- 本轮确认并修复 **9 项**缺陷，其中 **1 项为阻塞级**：`McLoginStart` 里的非法强转让
  **所有登录方式（离线 / 正版 / Nide / Auth）一律失败**，启动页停在「登录失败」，无法启动游戏。
  该问题只有在真实运行启动器时才会暴露，编译期与静态编译警告均无提示。
- 回归结果：Alpha / win-x64 Release 构建 **0 错误**；启动冒烟到「登录 Finished」，
  `Log1.txt` 无 `E` 级日志、无 `InvalidCastException`。
- 另复核了 dev.6 清单中的 M1–M8 / S1–S14：其中大部分（ModJava 约束空数组、MyBitmap
  `ReadExactly`、ModNet `OnFail` 空 `Ex`、取消链 CTS、`FailCount` 原子递增、MyBitmap 静态缓存、
  皮肤上传重试上限）在 alpha 已落地，本轮不重复处理。

## 二、修复清单

| 编号 | 严重度 | 位置 | 现象 | 根因 | 修复 |
|---|---|---|---|---|---|
| A1 | **阻塞** | `Modules/Minecraft/ModLaunch.cs` `McLoginStart` | 所有登录方式失败，启动页提示登录失败，无法启动游戏；日志 `Unable to cast object of type 'LoaderTask<McLoginLegacy,McLoginResult>' to type 'McLoginResult'` | VB 原文是 `Loader.Output` 晚绑定；迁移写成了 `((dynamic)(McLoginResult)((object)Loader)).Output`，先强转成 `McLoginResult` 必然抛 `InvalidCastException` | 按实际加载器类型（`LoaderTask<McLoginMs/McLoginLegacy/McLoginServer, McLoginResult>`）取 `Output`，未知类型显式报错 |
| A2 | 高 | `Controls/MyLoading.xaml.cs` `RefreshText` | 加载失败时错误文本不显示，反而抛 `InvalidCastException`（登录失败场景直接看不到原因） | 同类迁移痕迹：`((dynamic)(Exception)((object)State)).Error` 把 `ILoadingTrigger` 强转成 `Exception` | 改为 `State is ModLoader.LoaderBase ? .Error : null` |
| A3 | 高 | `Modules/Base/ModBase.cs` `StartProcess` | 「打开网页」「打开日志/崩溃报告」「以管理员重启」全部失效：前者弹「无法打开网页」，后者静默不提权 | .NET Core 起 `ProcessStartInfo.UseShellExecute` 默认 `false`（.NET Framework 为 `true`），URL / 目录 / 非可执行文件无法由 `CreateProcess` 解析；`Verb="runas"` 在 `UseShellExecute=false` 时被忽略 | 在唯一入口按目标类型判定：URL、已存在的目录、非 `.exe/.com` 文件、带 `Verb` 一律切到 shell；`.exe/.com` 保持直接启动 |
| A4 | 中 | `Modules/Minecraft/ModWatcher.cs` | 多实例 / 状态回调并发时可能丢监视器；`Instance` 为空时退出判定抛 NRE | `McWatcherList` 的「读旧表→建新表→写回」非原子；`Instance.ReleaseTime.Year` 未判空 | 加锁串行化整表替换，状态回调固定取快照枚举；`Instance` 判空后再取发行时间 |
| A5 | 中 | `Modules/Minecraft/ModMinecraft.cs` `McInstance.JsonObject` | 版本 JSON 存在循环继承（A→B→A）时逐层递归构造，最终 `StackOverflow`，启动器无提示直接退出 | 继承合并通过 `new McInstance(父版本)` 递归，无深度护栏；`StackOverflow` 无法被 catch | `[ThreadStatic]` 记录继承链深度，超过 8 层抛可捕获异常并记录「疑似循环依赖」 |
| A6 | 中 | `Modules/ModMusic.cs` `DequeueNextMusicAddress` | 音乐列表初始化失败时下一次播放抛 NRE | `MusicWaitingList` 可能保持 `Nothing`，原写法直接 `.Any()` | 与 `MusicAllList` 同等判空，初始化失败时安全返回 `null` |
| A7 | 中 | `Modules/Base/MyBitmap.cs` | 图片加载失败的回退路径对非 `Bitmap` 资源抛 `InvalidCastException`，真实原因被吞掉 | `TryFindResource` 可能返回 `BitmapSource` / `ImageBrush`，原写法一律强转 `System.Drawing.Bitmap` | 按 `System.Drawing.Bitmap` / `BitmapSource` / `ImageBrush` 三种类型分别取用，仍无资源才走「1×1 占位 + 抛原始原因」 |
| A8 | 低 | `Modules/Base/ModAnimation.cs` `AniType.TextAppear` | 回弹缓动下文本下标可能越界，抛 `ArgumentOutOfRangeException` | 进度可越过 0~1，`TextCount` 未钳制 | `TextCount.Clamp(0, Text.Length)` 后再 `Substring` |
| A9 | 低 | `Modules/ModMain.cs` `Feedback`；`Modules/Base/ModValidate.cs` 入口 | 反馈流程任一后续步骤异常会冒到 UI；输入校验传入空字符串引用时抛 NRE | VB 的 `On Error Resume Next` 未完整等价；各校验规则直接按字符串使用入参 | 反馈补兜底 `catch (Exception)` + 日志；校验入口统一 `Text ??= ""` |

## 三、验证记录

1. **基线编译**（改动前）：`scripts\Build.ps1 -Channel Alpha` → 0 错误，
   产物 `pcl-next\bin-net10\Alpha\2.100.0.7-1.06\win-x64\`，构建标识 `1.06.g10d3dad...dirty`。
2. **启动冒烟（第一轮，修复前）**：运行产物 10s，`PCL\Log1.txt` 第 43–48 行：
   `加载器「登录」状态改变：Failed` + `Unable to cast object of type 'LoaderTask<…>' to type 'McLoginResult'`
   （`ModLaunch.cs:line 700`）。→ 定位 A1。
3. **Process.Start 实证**（当前 .NET / PowerShell 7.6）：
   - `UseShellExecute=false` + `https://example.com` → `系统找不到指定的文件`；
   - `UseShellExecute=false` + `C:\Windows` → `拒绝访问`；
   - `UseShellExecute=false` + `Verb="runas"` → 不抛异常但未提权（Verb 被忽略）。
   → 定位 A3。
4. **修复后编译**：0 错误，警告集合与基线一致（主工程 14 条，均为既有 `SYSLIB0021` /
   `CS0162` / `SYSLIB0037` / `WFO0003` / `NU1510`，无新增）。
5. **启动冒烟（第二轮，修复后）**：运行产物 12s，`PCL\Log1.txt`：
   `登录加载已开始` → `登录方式：离线（TestUser2）` → `登录加载已结束` → `登录 状态改变：Finished`，
   全日志无 `E` 级记录、无异常堆栈。

## 四、已确认但本轮不改（附原因）

| 项 | 位置 | 原因 / 后续 |
|---|---|---|
| 校验规则直调路径仍可能传 `null` | `ModPack` 等处直接 `new ValidateXxx().Validate(InstanceName)` | 入口（`ModValidate.Validate`）已兜底；直调点分散在安装流程，改动面大于收益，留待下一轮统一 |
| 动画线程无重入保护 | `ModAnimation.AniStart()` | 当前只有一个调用点；加了守卫后线程若异常退出将无法自愈，需先设计重启策略 |
| `--gpu` 缺第二个参数 | `Application.xaml.cs` | `e.Args[1]` 越界已被 `catch` 兜底为 `Fail` 退出，不构成崩溃 |
| `GetUuid` 惰性建锁竞态 | `Modules/Base/ModBase.cs` | 仅在首次并发调用时可能产生两个锁，伪 UUID 重复概率极低，暂不动 |
| 游戏完整启动链路 | 下载 / 启动 / 退出监控 | 本轮只验证到「登录完成」；启动真实实例需要可复现的 MC 环境，未纳入本轮 |

## 五、适用边界

- 所有改动均限定在 Windows 分支 `alpha-Windows` 的 `pcl-next` 源码与文档；
  未触碰 Linux / Android 工作区，未改版本常量、未打 tag、未发布。
- A1 / A2 / A3 属于「迁移语义差异」类缺陷，同类模式应继续用
  「`(dynamic)(具体类型)((object)x)` 强转」作为检索特征做静态排查。
