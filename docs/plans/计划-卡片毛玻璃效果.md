# 计划-卡片毛玻璃效果（应用内模糊，零反射方案）

> 立项时间：2026-11-12 17:20
> 分支：`dev.6-Windows`
> 关联调研：`.workbuddy/memory/2026-11-12.md`（PCL2-CE 深色模式与模糊效果调研）、
> `PCL2-CE-与-pcl_next-对比分析.md`

## 1. 目标

给 pcl-next 的卡片增加「应用内毛玻璃」：卡片底色转为半透明，透出其下方**经过高斯模糊的
窗口背景**，形成磨砂质感，而不是目前「近乎不透明的纯色卡片 + 一层阴影」。

约束（用户已裁决的方向与本项目硬规则）：

- 只做 Windows 线，不动 Linux / Android 仓库。
- 不推翻已落地的深色主题与旧/新版切换（`94ccec4` / `7910162`），亮色与深色都要能正常显示。
- 不得出现「点了没反应」：默认取 0（关闭），开启后若缺少背景图立即给出明确提示，
  设置项可实时调强度或关闭。理由见 §3.4（当前用户所有运行目录均无背景图，
  默认开启只会降低卡片文字对比度却看不到模糊，属净负收益）。
- 编译必须带真实 RID（`win-x64`），产物只落 `bin-net10` 三段树；提交用 conventional +
  `Build:` 行，禁 `git add -A`。

## 3. 现状分析

### 3.1 CE 的做法与本项目的差距

PCL2-CE 写了 5 套模糊实现，但实测只有 WPF 内置 `BlurEffect` 真正生效：
`BlurBorder.CreateOptimizedBlurEffect()` 三条分支最终都返回 `BlurEffect`，
`EnhancedBlurEffect` 零调用点、`AdaptiveBlurEffect`(HLSL) 从未实例化、
`SamplingBlurProcessor` 只被测试调用；CE 也没有 DWM / 亚克力 / Mica P/Invoke。
真正生效的是 `BlurBorder` 把下方可视树重绘到 `DrawingVisual` 再挂 `BlurEffect`，
做出卡片 / 左栏 / 弹层的毛玻璃。

pcl-next 已有的模糊只有两处：

- `FormMain.xaml.cs:975-982`：背景图 `ImgBack` 的 `BlurEffect` + 负 Margin，
  由设置项 `UiBackgroundBlur`（0–40）控制，默认 0（关闭）。
- `PageDownloadInstall.xaml.cs:1062-1100`：下载页瞬时浮层用
  `RenderTargetBitmap` 拍窗口快照 + `BlurEffect(Radius=30)`，属未提交的另一条工作线。

**缺的是卡片层**：`MyCard.cs:105-107` 的 `MainBorder` 是普通 `Border`，
底 `ColorBrushCard` 亮色 `#F5FFFFFF`（α=245/255≈0.96）、深色 α≈0.824，
几乎不透，背后内容看不到。

### 3.2 为什么不用 CE 的 `BlurBorder` + `BackgroundPresenter`

`BackgroundPresenter.cs` 深度反射 WPF 私有成员：
`UIElement._drawingContent`、`DrawingVisual._content`、`Visual._offset`、
`UIElement.RenderOpen` / `OnRender`、`VisualBrush.GetContentBounds`，
并用 `CreateDelegate` 强转。这些是运行时内部实现细节，跨 .NET 版本升级会直接
`NullReferenceException`（源码里用 `!` 抑制了空值）导致整窗 UI 崩溃。
`BlurBorder.OnRender` 又依赖 `BackgroundPresenter.DrawBackground` / `DrawVisual` /
`ForceRender`，无法只搬一半。

此外这两个文件头部明确标注来自 **EleCho.WpfSuite / MIT**，整包移植需要额外的
许可归属处理；`AllowsTransparency=True + WindowStyle=None` 的分层窗口与
逐卡片 Effect 叠加也是 CE 没验证过的组合。

### 3.3 本轮采用的替代方案

只用 WPF 公开 API，做**全局一层**而不是逐卡片一层：

```
PanForm (Grid, Row 1)
 ├─ ImgBack (Canvas)              窗口背景图，最底
 ├─ PanBlurBackdrop (Border)      ← 新增：Background = VisualBrush(ImgBack)，Effect = BlurEffect
 ├─ PanLeft / PanMain             侧栏与主内容
 └─ MyCard.MainBorder             卡片底 → 半透明 ColorBrushCard
```

- `VisualBrush.Visual = ImgBack`：两者同在 `PanForm` 第 1 行、同尺寸，
  坐标天然对齐，**不需要**计算 `Viewbox` 偏移；`ImgBack` 是叶子 `Canvas`，
  不在 `PanBlurBackdrop` 的可视子树里，不会形成循环引用。
- `Effect` 只挂在 `PanBlurBackdrop` 这个**无子元素的 Border** 上，
  因此模糊的只有背景，卡片里的文字和控件完全清晰。
- 全局只渲染一次源视觉 + 一次模糊，比 CE 的「每张卡片一份 BlurBorder」
  开销低得多；设置页十几张卡片也不会叠十几份 Effect。
- `VisualBrush` 是实时的，背景图切换 / `UiBackgroundBlur` 变化时自动跟随，
  无需快照失效与重拍逻辑。

### 3.4 无背景图时的降级（2026-11-13 补充裁决）

实测用户所有运行目录的 `PCL/Pictures/` 均为空，即**没有自定义背景图**：
`ImgBack` 此时是空的 `Canvas`（`Background=null`、`Visibility=Collapsed`），
`VisualBrush` 拍不到任何像素，模糊层纯透明。纯色/线性渐变背景即使模糊也与
原图肉眼无差，这是 WPF 应用内毛玻璃的固有限制（CE 同样依赖背景视觉内容）。
因此：

- `UiCardBlur` 默认改为 **0**；默认态与改动前逐像素一致，零回归。
- 用户把滑条调到 >0 且无背景图时，`ModBlur.Apply()` 隐藏模糊层并**弹一次提示**
  （静态标志节流），明确指引去「背景图片」添加图片；卡片仍按 `UiCardBlur > 0`
  变半透明，作为「开关已生效」的可见反馈，但不做无意义的全屏模糊渲染。
- 设置背景图后 `PageSetupUI.BackgroundRefresh` 会调用
  `UpdateBackgroundAndTitleBar()`，其末尾的 `ModBlur.Apply()` 立即让磨砂生效，
  无需重启；`VisualBrush` 实时指向 `ImgBack`，图片切换自动跟随。

## 5. 改动要点

- `ModBlur.Apply()` 幂等：`_backdropBrush` 只创建一次；`FrmMain` 未加载时直接返回；
  整个方法包 `try/catch`，失败只记日志并退化为不显示模糊层，**不影响主界面**。
- `UiCardBlur = 0` 时 `PanBlurBackdrop.Visibility = Collapsed` 且 `ColorCard.A`
  回到原值，与改动前完全一致（这是回滚判据）。
- **无背景图降级**：`Apply()` 判 `ImgBack.Background is not null && Visibility == Visible`；
  不满足则隐藏模糊层并弹一次提示（详见 §3.4）。`Apply()` 挂在
  `FormMain.UpdateBackgroundAndTitleBar()` 末尾，覆盖启动、背景图刷新与背景设置变化
  三条路径；`UiCardBlur` 的 `OnChanged` 也会直接调用，保证拖动滑条即时响应。
- `OnChanged: (_) => { ModSecret.ThemeRefresh(); ModBlur.Apply(); }`：
  `Settings.Set` 先写缓存再触发事件，所以两处读到的都是新值；
  `ThemeRefresh()` 无参调用会重算全部资源键，卡片透明度即时刷新。
- `ColorCard.A`：亮色 245 → 180（≈0.71），深色 ≈210 → 165（≈0.65）。
  只改 `ColorBrushCard`，`Popup` / `Tooltip` / `Sidebar` / `Window` 等语义面不动，
  避免弹层、侧栏一起变透导致文字对比度不足。
- 半径取 `UiCardBlur` 原值（0–40），`KernelType=Gaussian`、
  `RenderingBias=Performance`；`Math.Max(1d, radius)` 防止 0 值误传。
- 设置页滑条放在「叠加彩色背景」附近（始终可见），不放进
  `PanBackgroundBlur` 那种 `Visibility=Collapsed` 的可折叠行，避免用户找不到开关。

## 6. 回归影响面

- **亮色 / 深色两套主题**：`ColorCard.A` 走 `ThemeRefresh`，两套都会重算；
  旧版 HSL 深色与新版 OKLCh 深色共用同一处 `ColorCard` 调整，不会混搭。
- **卡片文字对比度**：白底 α 从 0.96 降到 0.71 后，若背景图很亮，
  深色文字对比度会下降；这是本功能固有的取舍，滑条调到 0 可完全恢复。
- **性能**：全局一层 `BlurEffect`；`RenderingBias=Performance`；
  低性能机器可把滑条调小或关掉。Tooltip 需写明这一点。
- **分层窗口**：`AllowsTransparency=True + WindowStyle=None` 下 `ImgBack` 已经在用
  `BlurEffect` 且实跑正常，本轮复用同一机制，不引入 Win32 调用。
- **无背景图时**：默认值为 0，界面不变；用户主动开启时模糊层隐藏、弹一次提示，
  卡片仅变半透明（可见反馈），不会出错、不会变黑、不会白白跑一次全屏模糊。
- **下载页浮层**：其 `MakeBackdropBlur` 独立拍快照，与本层无耦合；
  两层同时出现时浮层快照会包含模糊层，属预期叠加。

## 7. 验证步骤

1. `dotnet build pcl-next/pcl-next.csproj -c Release -r win-x64 --self-contained`
   → 0 错误，核对无本轮新增警告；产物落 `bin-net10\Dev\<版本>-<构建号>\win-x64\`。
2. GUI（由用户执行）：
   - 默认启动：滑条应为 0，卡片外观与改动前一致；
   - 未设置背景图时把滑条拖到 12：应弹一次「需要自定义背景图」提示，卡片变半透明；
   - 在「背景图片」中添加一张图片后：磨砂效果立即出现，无需重启；
   - 滑条拖到 0：卡片恢复改动前的不透明底、模糊层消失；拖回 20：立即变模糊；
   - 切到「深色」主题（新版 OKLCh / 旧版 HSL 各一次）：卡片半透明且文字可读；
   - 设置一张背景图并调「背景模糊」：两层模糊应叠加而不出现错位、黑边、闪烁；
   - 滚动设置页、切换页面、打开弹层：无掉帧、无残影、无循环引用异常；
   - 重启启动器：滑条值与效果保持。
3. 判定标准：编译 0 错误 + 上述逐项通过；若出现整窗黑屏 / 卡片文字发糊 /
   明显掉帧，先把滑条调 0 并按 §8 回滚，本轮不予保留。

## 8. 回滚方案

- 用户侧即时回滚：把「卡片毛玻璃」滑条设为 0，效果与改动前逐像素一致，无需重装。
  （当前默认即为 0，等于默认不启用。）
- 代码侧回滚：`git revert` 本轮提交并删除新增的 `ModBlur.cs`；
  `ColorBrushCard` 的 α 由 `ThemeRefresh` 恢复原值，`FormMain.xaml` 多出的
  `PanBlurBackdrop` 恒为 `Collapsed`，不影响任何布局。
- `UiCardBlur` 是新增设置项，回滚后残留的 ini 键不会被读取，无副作用。
- 不修改《计划-深色主题.md》《计划-深色主题重做-OKLCh.md》的历史结论。

## 合规边界

- **不复制任何 PCL2-CE 源码文件**：`ModBlur.cs` 为独立编写，只使用
  `System.Windows.Media.VisualBrush` 与 `System.Windows.Media.Effects.BlurEffect`
  等 WPF 公开 API；未移植 `BlurBorder.cs`、`BackgroundPresenter.cs`
  （两者来自 EleCho.WpfSuite / MIT），也未使用 HLSL、`.ps` 着色器或 `fxc` 工具链。
- **不引入任何 NuGet 包 / 第三方许可 / P/Invoke**：无 DWM、亚克力、Mica、
  `SetWindowCompositionAttribute` 等窗口级材质调用，因此不触碰
  `PLATFORM_RELEASE_ENABLED` 与非 Windows 制品分发的合规门槛。
- CE 侧本轮只借鉴一个**事实性结论**（「CE 实际生效的是 WPF 内置 BlurEffect」）
  与「模糊层与内容层分离」的通用 UI 思路，二者不构成可版权保护的表达式。
- 未改动关于页署名、品牌蓝主色义务、正版劝导与赞助链接，未新增分发通道；
  `docs/合规/跨平台授权问询.md` 的暂不发送决定继续有效。
- 本轮为 Windows 自用改版的本地 UI 渲染逻辑，不涉及 MC 本体下载门控、
  遥测、自动更新等合规敏感链路。
