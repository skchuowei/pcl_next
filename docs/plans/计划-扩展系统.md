> 依据：《AGENTS.md》§3.1/§3.2、《分支与发布规范.md》§1.1（许可 L1–L5）、《dev.4公布标准.md》§2.2。

## 0. 需求定调（用户口径 → 工程口径）

用户要求：**「自由度高一点，但要有约束作用（如明确的某函数不能调用）」**。

这条要求翻译成工程语言，是两句话：

1. **自由度** = 扩展点要够宽。插件不只是换主题，还要能加页面、加命令、加下载源、加资源站、改启动参数模板、挂事件钩子。
2. **约束** = 不靠文档喊「请不要」，而是**结构上拿不到内核对象**、**加载期扫出禁用调用就整包拒绝**、**危险动作必须过宿主门禁**。

「某函数不能调用」的落地方式必须是我方**自动判定**，不能依赖插件作者自觉。做法见 §5。

**一句话设计**：插件只能引用 `PCL.Sdk`（接口 + DTO），拿不到内核实现；在此基础上做调用点黑名单扫描（fail-closed）+ 危险能力门禁 + 行为审计。

## 1. 目标

### E0 规范冻结（本文主体，0.5–1 人日）

产出：清单 schema（`plugin.json`）、能力词表（capabilities）、扩展点清单、**禁用调用黑名单**、版本兼容策略、市场准入规则。全部落到本文，作为后续实现的唯一口径。

### E1 声明式扩展（dev.5，1–2 人日）

不执行任何插件代码，只读数据包：镜像源、主题/图标包、启动参数模板、外部工具挂载、整合包来源。**零 ABI 风险**，能立刻满足一部分「第三方扩展」的真实需求。

### E2 代码级宿主（内核 API 冻结后，5–7 人日）

`AssemblyLoadContext` 隔离加载 + 引用程序集白名单 + 黑名单扫描 + SDK 门面注入 + 扩展点注册 + 失败隔离。

### E3 信任与权限（2–3 人日）

签名（可选）+ TOFU 信任 + 能力授权 UI + 审计日志 + 越权自动禁用。

### E4 索引分发（2–3 人日）

GitHub 托管的社区索引 `index.json`（官方预索引 + 实时搜索补充）。**不自建服务端**。

### E5 L2 受限能力（3–5 人日）

文件（限目录）、网络（限域）、进程（限可执行白名单）三类能力的细粒度开放。

**可验证标准**：E1 数据包可装可禁用且不执行代码；E2 一个故意调用 `Process.Start` 的测试插件被**整包拒绝**且 UI 显示命中行号；E3 越权调用被拦并留审计；全流程不影响启动器启动时间超过 300ms。

## 3. 现状分析

### 3.1 我们有什么（可以作为扩展点挂载的锚）

| 锚点 | 现状 | 可承载的扩展 |
|---|---|---|
| `PCL.Download` 的 `IResourceProvider` / `ResourceProviderRegistry` | ✅ 已抽象，注册表可插拔 | **新资源站**扩展点（最干净的一个） |
| `IDownloadEngine` + `DownloadSource` | ✅ | 下载源/镜像扩展、限速策略 |
| `PCL.Download` 的 `IResourceApi` | ✅ | 请求签名、代理 |
| VB 侧 `PageSelectLeft` 导航 | 在 `PageSelectLeft.xaml.vb` 里手工 `PanList.Children.Add` 逐项拼装，`RestrictMcDownload` 也是内联 `If` 门控 | 导航页扩展点（需先抽出注册表，E2 改造项） |
| `Settings`（`Settings.Get/Set`） | 全局静态 | 设置项扩展点（需包一层 SDK） |
| `ModEvent.vb` | 是 WPF 事件附加属性，**不是通用事件总线** | 事件钩子扩展点需要新建，不能复用 |
| `ModDownloadPolicy` | ✅ 部署期配置 | **合规门禁，插件不得绕过** |

### 3.2 参考实现为什么不能照抄

`pcl_nex插件参考/PCL2-Nex-dev` 走的是 **Mixin / IL patch** 路线：14 个文件的自研 Mixin runtime + 6,467 行插件服务（其中市场服务 1,494 行），清单里绑死 `pclCoreVersion`。

- **它能成立的前提是「不拆内核」**——因为拿不到扩展点，所以直接改 IL。这跟我们 §1（T2）的方向相反。
- **它的代价是版本脆弱**：内核任何一个方法签名变化都可能让插件运行时崩溃，而崩溃点在 IL 层，堆栈不可读。
- **它的清单里 `pclCoreVersion` 是硬绑**——在重写期（半年内 API 会反复变）做这件事，等于每版废掉一批插件。

**结论**：不采用 Mixin 路线。仅在需要「插件改内核行为」且 SDK 未覆盖时，作为**最后手段**评估（且必须人工审核 + 用户显式二次确认），不进入默认路径。

### 3.3 已知风险（行业共性）

插件 = 任意代码执行。同进程 .NET **做不到真沙箱**（不能像浏览器那样隔离）。所以本方案的定位必须说清楚：

> 约束的目标是**防误用、抬高恶意成本、事后可审计**，不是「保证恶意插件无害」。

用户装插件时的心理模型应该是「装一个你信任的软件」，而不是「装一个安全的扩展」。这一点要写进 UI 文案与文档，不做安全承诺。

## 5. 改动要点

### 5.1 自由度分级（插件作者看到的四档）

| 档 | 名称 | 能做什么 | 门槛 |
|---|---|---|---|
| L0 | 声明式 | 镜像源、主题、图标、参数模板、外部工具、整合包来源 | 拖进目录即生效，不执行代码 |
| L1 | 沙箱插件（默认） | 全部**扩展点**：页面、命令、事件钩子、资源站、设置项、CLI 子命令；文件/网络/进程**只能通过 SDK 接口请求** | 无签名要求；能力逐项声明 + 用户首次授权 |
| L2 | 受信插件 | 在 L1 基础上，获得受限的直连文件（指定目录）、网络（指定域名）、进程（指定可执行）能力 | 签名 + 用户显式二次确认 + 能力清单可视化 |
| L3 | 内置 | 等同内核一部分 | 仅本仓库代码，不走插件通道 |

**关键**：L1 的「自由度」体现在**扩展点数量**，而不是「能不能调危险 API」。绝大多数有意义的扩展（换源、加站、加页面、加命令）在 L1 就够用，不需要放开危险能力。

### 5.3 「某函数不能调用」怎么真正拦住

**三层，从硬到软：**

**第一层：结构约束（最硬）**

- 插件包只允许引用 `PCL.Sdk`，**不得**引用 `PCL.Core` / `PCL.Download` / `pcl-next`(VB) / WPF 程序集。
- 加载期扫描 `AssemblyRef` 表：出现禁用程序集名 → **整包拒绝**（fail-closed），提示「本插件引用了内核内部程序集，不可加载」。
- 效果：插件在源码层面就 `new` 不到内核对象，也就无从调用内核内部函数。这比「函数黑名单」可靠得多——黑名单永远列不全，结构约束不用列。

**第二层：调用点黑名单（明确禁用的 BCL 面）**

用 `System.Reflection.Metadata`（PEReader）扫描插件程序集的 `TypeRef` / `MemberRef` / 带 `MethodImport`（P/Invoke）的 `MethodDef`，命中下列任一即拒绝：

| 类别 | 禁用目标 | 替代路径 |
|---|---|---|
| 进程 | `System.Diagnostics.Process`（`Start`/`Kill` 全部） | `IProcessLauncher`（L2 才可申请） |
| 注册表写 | `Microsoft.Win32.Registry` 的 `SetValue`/`CreateSubKey`/`DeleteSubKey*` | 只读需声明 `registry.read`；写一律禁止 |
| 破坏性文件操作 | `File.Delete` / `Directory.Delete` / `File.Move`（覆盖式） | `IFileAccess`（限目录 + 回收站语义） |
| 自加载代码 | `Assembly.Load*` / `LoadFrom` / `AssemblyLoadContext` 构造 / `Activator.CreateInstance(string)` | 禁止（防止绕过扫描加载第二份未审代码） |
| 运行时绕过 | `System.Runtime.Loader.*`、`Type.GetType(string)` 指向非 SDK 程序集 | 禁止 |
| 互操作 | 任意 `DllImport` / `LibraryImport` / `Marshal` / `NativeLibrary` / `unsafe` | 禁止（csproj 必须 `AllowUnsafeBlocks=false`） |
| 进程级 | `Environment.Exit` / `FailFast` / `Environment.FailFast` | 由宿主统一退出 |
| 序列化 | `BinaryFormatter` / `NetDataContractSerializer` | 禁止 |
| UI 越权 | `System.Windows` 下除 SDK 暴露的抽象外的类型 | 用 `IPageExtension` 等 |

**第三层：能力门禁 + 审计（运行期）**

- 危险动作只有宿主实现能用；插件拿到的都是接口。宿主在每次调用前检查「manifest 声明 + 用户授权」，不匹配 → 抛 `CapabilityDeniedException`。
- 每次能力调用写审计（谁、什么能力、什么参数摘要、结果）；越权计数超阈值（如 3 次）→ 自动禁用该插件并在 UI 明示。

**诚实边界（必须写进文档与 UI）**

反射仍可能绕过静态扫描（例如通过已注入的对象反查成员）。所以：

- 定位是**约束 + 成本**，不是安全边界；
- L2 必须「签名 + 用户显式确认 + 能力清单可视化」；
- 插件页文案明确：「插件拥有你授予的权限，请只安装你信任的来源」。

### 5.4 清单格式（E0 冻结初稿）

```json
{
  "schema": 1,
  "id": "example.mirror-pack",
  "name": "示例镜像源包",
  "version": "1.0.0",
  "sdk": "1.0",
  "level": "L1",
  "entry": "lib/Example.Mirror.dll",
  "capabilities": ["net.outbound:*.bmclapi2.bangbang93.com", "fs.read:${instance}"],
  "extensions": ["download.source", "settings.page"],
  "description": "…",
  "homepage": "https://…",
  "license": "MIT"
}
```

校验规则：

- `schema` / `sdk` 主版本不匹配 → 拒绝加载并提示「需更新启动器或插件」；
- `capabilities` 出现词表外的项 → 拒绝（防止拼写绕过）；
- `entry` 必须位于包内且为相对路径（防路径穿越）；
- 包内不得含 `.exe`/`.dll` 之外的本地库（`.so`/`.dylib`/`.node` 一律拒）。

### 5.5 合规红线（不可协商）

| 红线 | 依据 | 落地 |
|---|---|---|
| 插件**不得**绕过 `ModDownloadPolicy` 提供 MC 下载 | 本分支合规前提（`ModDownloadPolicy.vb`） | 清单校验 + `IDownloadEngine` 门禁：策略禁用时插件调引擎直接失败 |
| 不得提供「赞助解锁」类功能/表现 | 许可 L5 | 市场准入规则明令禁止；审核项 |
| 主色相保持蓝色 | 许可 L5 | 主题插件允许改配色，但默认主题与「官方皮肤」保持蓝色 |
| 插件不得暗示为 PCL 官方出品 | 许可 L1/L3 | 市场页面强制显示「第三方插件」标识 + 作者 |
| 分支与 SDK 开源 | 许可 L3 | `PCL.Sdk` 与《扩展规范》随仓库公开 |
| 不内联参考实现源码 | 第三方许可不明 | `pcl_nex插件参考` 只作思路参考，不复制代码；如要复用需先核实其许可证 |

### 5.6 兼容策略

- `sdk` 采用 `主.次`：**主版本不同 = 不兼容**（拒绝加载并提示）；**次版本前进 = 兼容**（新 API 只增不改）。
- 内核 API 冻结时同步发布《SDK 兼容承诺》：`[Obsolete]` 至少保留 **2 个次版本**再删。
- **冻结之前不允许任何人发布「依赖内核内部」的插件**——这也是 E2 必须等 T2 的原因：早放开的代价是把一个还在变的内部结构固化成对外契约。

### 5.7 失败隔离（不做这层，插件会变成崩溃源）

- 单插件加载超时 2s、总预算 5s，超时插件降级为「已禁用」并记录；
- 插件回调异常一律在宿主侧 catch，计数并显示「该插件出错 N 次」，不向用户弹崩溃框；
- 插件页面走独立 `Dispatcher` 异常处理，不允许触发主程序 `DispatcherUnhandledException` 全局逻辑；
- 插件禁用/卸载后必须能在**不重启**的情况下生效（服务类扩展点需支持注销）。

## 7. 验证步骤

**E0**：文档评审（清单 schema / 能力词表 / 黑名单 / 扩展点清单四项齐备），无需构建。

**E1**

```bash
# 装一个声明式包 → 设置页出现条目 → 禁用后镜像源恢复默认
pclcli ext install --file ./example.mirror-pack.zip
pclcli ext list            # 期望 level=L0，capabilities 空
pclcli ext disable example.mirror-pack
```

**E2**（黑名单验收，必须有反例）

```bash
# 正例：合规插件加载成功
pclcli ext install --file ./ok-plugin.zip && pclcli ext list   # 期望 enabled
# 反例 1：直接引 Process.Start → 整包拒绝
pclcli ext install --file ./bad-process.zip                    # 期望退出码 6，输出命中行号
# 反例 2：引用 PCL.Core → 结构约束拒绝
pclcli ext install --file ./bad-internal-ref.zip                # 期望退出码 6
# 反例 3：DllImport → 拒绝
pclcli ext install --file ./bad-pinvoke.zip                     # 期望退出码 6
```

**E3**：越权调用 → `CapabilityDeniedException` + 审计记录 + 计数达阈值自动禁用。

**E5**：L2 能力 → 目录白名单外访问被拒；域名白名单外请求被拒。

| E1 引发设置/下载异常 | 关闭「设置 → 扩展」入口，`DeclarativeExt` 停止加载（保留已安装清单文件，不删用户数据） | 用户已装包原样保留，恢复后可再用 |
| E2 加载器导致启动崩溃 | 启动时加 `--safe-ext` 跳过全部插件；连续两次崩溃自动进入安全模式并提示 | SDK 工程保留 |
| 黑名单误杀正常插件 | 单条规则降级为「警告」需**用户显式开启**并记入待核对清单，不得全局关掉扫描 | 其余规则继续生效 |
| E4 索引服务不可用 | 索引只是列表来源，退回「从本地文件安装」 | 本地安装路径始终可用 |

任何回滚按《AGENTS.md》§六 出具回退报告（`回退报告-扩展系统.md`），禁止静默回退。
