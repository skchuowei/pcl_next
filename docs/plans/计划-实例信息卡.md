# 计划：实例设置概览页「实例信息」卡（从 PCL2-CE 合并，C# 落地）

> 来源对照：CE `Pages/PageInstance/PageInstanceOverall.xaml(.cs)` + `PageInstanceOverallViewModel.cs` +
> `Modpack/Core.cs` + `Comp/Project.cs` + `Comp/Request.cs`。
> 本计划在 pcl-next 现有 C# 架构内复刻该卡片，不照搬 CE 的 MVVM/服务分层。

## 1. 目标

在实例设置「概览」页（`PageInstanceOverall`）新增一张「实例信息」卡，对齐截图内容：

- 本地信息行：启动次数、整合包版本、Minecraft 版本、已安装 Mod 加载器及版本；
- 在线整合包卡：若实例由 CF / Modrinth 整合包安装而来，按留存的工程 ID 联网拉取工程信息，
  显示名称 / 副标题 / 标签 / 描述 / 下载量 / 来源；拉取失败或无留存 ID 时隐藏该卡。

可验证标准：
- 全新构建 0 个 C# 编译错误（exe 被运行中实例锁定除外）；
- 概览页信息行与实例 JSON 解析结果一致；CF / Modrinth 整合包实例显示在线卡，普通版本不显示。

## 2. 前置条件与阻塞项

- 基线：`scripts/Build.ps1 -Channel Dev` 源码可编译（本次基线仅 exe 被运行中实例 PID 13524 锁定，
  无 CS 错误）。
- 复用既有能力，不新写网络层：
  - `McVersion`（PCLCS）：`VanillaName` / `ModLoaderVersions` / `OptiFine` / `ModLoaders`；
  - `ResourceProject.FromProjectIds(ids, platform)`：按 ID 批量联网取工程；
  - `ResourceProject.ToResourceItem(showMcVersionDesc, showLoaderDesc)`：工程 → `MyResourceItem`；
  - `MyListItem`：`Title / Info / Logo`；`ModBase.ReadIni / WriteIni` 直读直写实例 `PCL\Setup.ini`。

## 5. 改动要点

### 5.1 实例级启动计数（ModLaunch.cs）

- 位置：`McLaunchRun` 内现有 `Settings.Set("SystemLaunchCount", ... + 1)` 之后。
- 实例对象：`ModMinecraft.McInstanceSelected`；为空则跳过（避免空引用）。
- 读取 `VersionLaunchCount`（默认 0），+1 后 `ModBase.WriteIni` 回写
  `Instance.PathVersion + "PCL\Setup.ini"`。

### 5.2 整合包元数据留存（ModModpack.cs）

- CurseForge（`InstallPackCurseForge`，manifest.json）：
  - `VersionModpackId` = `Json["projectID"]`；`VersionModpackVersion` = `Json["version"]`；
    `VersionModpackSource` = `CurseForge`；字段缺失则写空字符串容错。
- Modrinth（`InstallPackModrinth`，modrinth.index.json）：
  - `VersionModpackId` = `Json["projectId"]`；`VersionModpackVersion` = `Json["versionNumber"]`（缺失留空）；
    `VersionModpackSource` = `Modrinth`。
- 写入点：两个方法现有的「最终整理文件」`LoaderTask` 内、Logo 设置旁（与既有 WriteIni 同位置）。

### 5.3 概览页 XAML

- 在 `PanDisplayItem` 所在 `MyCard` 之后、「个性化」卡之前新增：
  - `MyCard Title="实例信息" x:Name="PanInfoCard"`；
  - `ContentControl x:Name="PanModpack"`（在线卡占位，无内容时 Collapsed）；
  - `WrapPanel x:Name="PanInfo"`，code-behind 直接 `Children.Add` 构造 `MyListItem`（与 next 其他页面动态构造列表项的惯例一致）。

### 5.4 信息行装配（code-behind，C#）

`RefreshInstanceInfo(McInstance Instance)`：

1. 清空 `PanInfo.Children`。
2. 启动次数行：`VersionLaunchCount`；0 → `RedstoneLampOff.png` + 「从未启动」；
   否则 `RedstoneLampOn.png` + 「已启动 N 次」。
3. 整合包版本行：`VersionModpackVersion` 非空 → `CommandBlock.png`。
4. Minecraft 行：`Version.VanillaName`，`Grass.png`。
5. 加载器行（按 `ModLoaders` 标志去重遍历）：
   Forge（`GoldBlock.png`）/ NeoForge（`NeoForge.png`）/ Fabric（`Fabric.png`）/
   LiteLoader（`Egg.png`）；版本取 `ModLoaderVersions[loader]`，空显示「未知版本」；
   OptiFine 单独行（`OptiFabric.png`，`Version.OptiFine`）。
6. 在线整合包卡：
   - 后台线程（`ModBase.RunInNewThread`）读 `VersionModpackId / Source`；
   - Source 为 `CurseForge` / `Modrinth` 且 ID 非空 → `FromProjectIds([id], platform)` 取首个；
   - `ModBase.RunInUi`：`project.ToResourceItem(false, false).Init()` 取控件，
     `IsHitTestVisible = false`（禁止跳转资源详情页，仅展示），加入 `PanModpack`；
   - 无结果 / 异常 → `PanModpack` Collapsed，记 warn 日志，不阻断信息行。

### 5.5 配置键惯例

- 不注册 `Settings.Entries`（与 `IsStar / DisplayType / Logo` 一致，走 `ReadIni/WriteIni`）；
- 键名前缀沿用 `Version`（实例独立配置）。

## 6. 回归影响面

- 仅新增读取与装配逻辑；不修改现有实例解析、下载、启动流程的判定分支。
- 实例级计数为新增键，老实例默认 0，行为回退到「从未启动」。
- 在线拉取失败静默降级为隐藏卡片，不影响页面其他部分。
- 需回归：普通版本实例概览页不出现在线卡；CF / Modrinth 整合包实例显示在线卡；
  启动一次后实例计数 +1，全局计数不变口径。

## 7. 验证步骤

1. `./scripts/Build.ps1 -Channel Dev -Configuration Release`（§0.3；产物落 `bin-net10/Dev/.../win-x64/`）；
   以 0 个 CS 错误为准；若 exe 被运行中实例锁定，关闭实例后重跑。
2. 冒烟：任选普通版本实例打开概览页，核对 MC 版本与加载器行；
   启动一次返回查看实例计数 +1。
3. 对 CF / Modrinth 整合包实例核对在线卡名称 / 标签 / 下载量 / 来源。
4. 收尾 `git status`，仅暂存本轮改动文件，确认无产物 / 用户目录被纳入版本库。

## 8. 回滚方案

- 全部为新增页面逻辑 + 四个实例 INI 键，无数据库 / 配置格式迁移；
- 回滚：`git revert` 本轮提交即可；老实例无新键时全部走默认值，无残留副作用。

## 9. 合规边界

- 仅复用既有 Modrinth / CurseForge 公开只读查询接口，不新增第三方分发通道；
- 不改动上游署名、关于页与许可相关内容。
