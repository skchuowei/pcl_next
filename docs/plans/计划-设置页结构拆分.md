## 1. 目标

### 1.1 问题陈述

设置页只有 6 个选项卡，但把大量互不相关的设置项塞进同一页，用户要在长页里滚动找项，且一页里卡片主题跨度极大（下载源 / 社区资源 / 更新提示 / 缓存目录 / 调试开关同处「其他」一页）。

### 1.2 量化现状（本工作区实测）

| 选项卡 | 卡片数 | 设置项 key | 行标签数 | 备注 |
|---|---|---|---|---|
| 启动 `PageSetupLaunch` | 4 | 27 | 10 | 4 张卡里 2 张默认折叠（皮肤、高级） |
| 联机 `PageSetupLink` | 2 | 2 | 2 | 内容最少，与「启动」主题相邻 |
| 个性化 `PageSetupUI` | 6 | **61** | 7 | **最严重的混合页**：主题/背景/音乐/标题栏/主页/功能隐藏 |
| 其他 `PageSetupSystem` | 6 | 17 | 14 | 下载 / 社区资源 / 辅助功能 / 启动器 / 调试 |
| UI 设置（测试）`PageSetupUIAdv` | 2 | 8 | 0 | 开发期试验台，混在正式设置导航里 |
| 我的账号 `PageSetupAccount` | 2 | 0 | 0 | 与「设置」语义弱相关 |
| **合计** | **22** | **115+** | — | 6 个导航项承载全部 |

### 1.3 验收标准（可机械核对）

1. 单选项卡设置项 key ≤ 30，单页卡片 ≤ 3。
2. 导航为「分组标题 + 条目」两级结构，分组 ≤ 4 个，条目 ≤ 11 个。
3. 每个选项卡的卡片主题属同一语义域（不存在「下载源 + 关于文本」这种拼盘）。
4. 左栏条目超出可视高度时可用滚轮滚动，不裁切。
5. 既有 `SettingService.Key` 全部保留，用户旧配置不丢。

## 3. 现状分析

### 3.1 结构对照（CE vs pcl_next）

| | PCL2-CE | pcl_next（现状） |
|---|---|---|
| 导航层级 | 分组标题 + 条目（游戏 / 工具 / 启动器 / 关于） | **扁平 6 条，无分组** |
| 页数 | 11（启动、Java、管理、联机、个性化、语言、杂项、关于、更新、反馈、日志） | 6 |
| 单页卡片 | 1–4 张（如「杂项」= 系统 / 网络 / 调试） | 2–6 张 |
| 语义边界 | 一页 = 一个对象（Java 一页、语言一页、更新一页、日志一页） | 一页 = 一堆对象（个性化 61 key） |
| 左栏 | `MyScrollViewer` 包裹，可滚动 | 裸 `StackPanel`，条目多了会溢出 |

CE 的拆分判据很明确：**「用户想改什么」而不是「代码在哪」**——想改 Java 就去 Java 页，想改语言就去语言页；`杂项` 只收「系统 / 网络 / 调试」三类真正的杂项。

### 3.2 pcl_next 的混合点（逐张卡）

- `PageSetupUI`：主题配色（12 套色板 + 深色）、标题栏 Logo、背景图片、背景音乐、主页预设与联网更新、功能隐藏矩阵——**6 类完全不相干的视觉/入口配置同页**，61 key 里没有一组超过 15 个。
- `PageSetupSystem`：文件下载源/线程/限速、社区资源命名规则、MC 更新提示、启动器公告与缓存目录、调试开关——**「网络下载」「通知」「启动器自身」「调试」四种语义混装**。
- `PageSetupLaunch`：启动参数、内存分配、离线皮肤、JVM 参数/启动前命令——皮肤是**游戏内形象**，与前两者不是同一决策；且两者默认 `IsSwapped`，藏在折叠里等于「有但不被发现」。
- `PageSetupUIAdv`：配色/动画试验台，属开发调试能力，却与正式设置平级排在导航里。

## 6. 回归影响面

- **配置兼容**：旧 key 全保留 → 老用户升级后设置不丢；但「功能隐藏」的粒度变化需要一次性迁移映射。
- **导航记忆**：若存在「上次停留页」记忆（`UiLastPage` / `Stack` 相关），新 ID 会让记忆指向错误页，需按标签而非数字保存。
- **动画**：`PageSetupLeft.PageChangeRun` 与 `MyPageLeft.TriggerShowAnimation` 逐条入场延迟按条目数自适应（`Delay += Math.Max(15 - Id, 7) * 2`），条目从 6 → 10 后入场动画时长变长，需确认可接受。
- **左栏宽度**：条目 10 项 + 3 组标题约 440px，窗口高度小于此值时依赖新增的 `MyScrollViewer`。
- **必须新增/更新**：`PageSetupLeft` 的页面切换冒烟用例；「导入设置 → 重启 → 各页值正确」用例。

**缺陷修复**：
1. 删除图标：原来硬编码的 `IcoDelete` 其实是均衡器图形，改用项目自带 `ModBase.Logo.IconButtonDelete`（垃圾桶），与启动页账号行一致。
2. 新建账号图标：工具栏按钮改用 `MyIconButton` + `LogoNewAccount` 的同一份 SVG（`MyButton` 控件只有文字，本身不支持图标，故不再用文字按钮承载）。
3. 切换账号列表跳动：根因是 `ModAccountList.SetCurrent` 必须把目标账号 `Promote` 到 `¨` 列表首位（首位即当前账号），而界面直接按存储顺序渲染。
   修法：`ModAccountList` 新增展示顺序缓存 `DisplayOrders`，`GetAll()` 末尾经 `ApplyDisplayOrder()` 稳定排序——
   老账号位置由首次枚举固定，新账号追加到末尾，`Rename` 原地替换名字，`Delete` 移除名字。
   影响面同时覆盖启动页账号面板（它同样走 `GetAll()`）。注意这是**会话内稳定**：
   重启后存储首位仍是当前账号，因此重启后当前账号排第一属预期行为。

### 9.7 图标统一与「编辑皮肤」入口下移（2026-11-14 第二轮反馈）

用户反馈四点：卡片里不该有「编辑皮肤」按钮，应在账号行的「编辑账号」弹窗（图2）里加「更改皮肤」；「添加账号」不要用图标按钮，直接文字；助手自绘/自选的图标不合格，改用用户提供的图标集 `D:\bing\MC\pcl_x\icons`。

**入口调整**：
- 账号卡工具栏只剩一个文字按钮「添加账号」（`MyButton`），不再用 `MyIconButton` 承载新增动作；卡片内「编辑皮肤」按钮整体删除。
- 「更改皮肤」进入 `EditAccount()` 弹窗，按账号类型出现在各自菜单首位：离线（修改玩家名 / 更改皮肤）、第三方 Auth（更改皮肤 / 修改密码 / 修改验证服务器）、Nide（更改皮肤 / 修改密码）、Ms（仅更改皮肤）。
- 分发逻辑 `ChangeSkinFor(Entry)`：离线走高亮改皮肤流程；正版提示后打开 `account.microsoft.com`；第三方提示后打开 `CacheAuthServerRegister`（缺失时回退 littleskin 注册页）。
- 「说明」卡文案同步改为「点击账号行的编辑按钮打开编辑菜单…」。

**图标体系**：用户提供的图标集是 24×24 **stroke 线框** SVG，而 `MyIconButton.Login`/`MyListItem.Logo` 只接受**填充**几何（Path.Fill），stroke 直接塞进去会画不出来。
处理方式：用 `Geometry.GetWidenedPathGeometry(Pen)` 把每个 SVG 图元（path/rect/circle/line/polyline/polygon）的描边**转成填充轮廓**，逐 figure 合并到一个 Nonzero 的 `PathGeometry`，再用 `GeometryConverter` 输出路径字符串；转换脚本一次性产出常量（未入版本库），并渲染对照图确认形状正确。
