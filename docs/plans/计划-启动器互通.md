# 计划：启动器互通（联机大厅兼容 PCL2-CE / 陶瓦）

> 状态：实施中（2026-11-15）
> 触发需求：用户「为了扩大业务，我们要实现启动器互通（增加设置项）」，选型为「全兼容 + 一个互通开关 + 自动识别码」，
> 加入外部大厅时「自动切到对方那套加密」，同时明确「我们也要数据加密」（自建大厅不降级为明文）。

## 1 目标

1. 联机页"联机设置"新增一个"互通目标"选择（仅 pcl-next / PCL2-CE / 陶瓦），默认"仅 pcl-next"，行为不变。
2. 加入侧**自动识别**四类邀请码，不需要用户手动选格式：
   - pcl-next 自研短码：`网名9-密钥5-端口4(hex)`
   - PCL2-CE 旧大厅码：整串 Base32（大写数字码），解码后 = 8 位数字网名 + 2 位数字密钥 + 十进制端口
   - 陶瓦（Terracotta）码：25 位 Base34，5 组 5 位，第 25 位是校验位，端口藏在数值里
   - PCL2-CE 新版 `U/XXXX-XXXX-XXXX-XXXX`（Scaffolding 码，**不含端口**，需另填端口）
3. 建房侧按"互通目标"生成对应格式的码，并按该格式对应的 EasyTier 参数建网，使**同一张码两个启动器都能用**（pcl-next 自己也能解析 CE/陶瓦码）。
4. 数据加密不降级：自建大厅显式 `--encryption-algorithm aes-gcm`（等价于当前默认值，只是写死以防未来 EasyTier 改默认），从不加 `--disable-encryption`。

## 2 前置条件与阻塞项

- EasyTier 2.6.4 本地二进制已验；`--encryption-algorithm` 支持 `xor/aes-gcm/aes-256-gcm/chacha20`，`--compression` 支持 `none/zstd`，
  `--enable-quic-proxy` / `--enable-kcp-proxy` / `--use-smoltcp` / `--multi-thread` 均为布尔开关。
- **已知硬边界（必须写进 UI 提示，不能承诺双向都通）**：PCL2-CE 2.6 的建房/加入走它自己的中心服务
  （`LobbyService.CreateLobbyAsync` 先查 NAID 登录，`JoinLobbyAsync → ScaffoldingFactory.CreateClientAsync` 连服务器取端口），
  所以"CE 用户输入我们的码进我们的大厅"仍受它的服务限制；真正的互通用法是"pcl-next 用对方的码加入对方大厅"，
  以及"双方各自建房、参数与码格式对齐后网络层可互通"。
- 阻塞：无（本轮不依赖 CE 运行，验证靠启动日志核对参数）。

## 5 改动要点

### 5.1 码算法（自己实现，不复制对方代码）

- **PCL2-CE 数字码**：Base32 字符表 `23456789ABCDEFGHJKLMNPQRSTUVWXYZ`，编码一个十进制数；
  解码后按位置切：前 8 位=网名、接着 2 位=密钥、其余=端口（十进制）。生成时网名首位取 1–9，避免前导零被吞。
- **陶瓦码**：Base34 字符表 `0123456789ABCDEFGHJKLMNPQRSTUVWXYZ`（无 I/O）。前 24 位是**小端** Base34 数字，
  `value = Σ digit[i] × 34^i`；第 25 位 = `Σ digit[0..23] % 34` 的字符作校验；端口 = `value % 65536`（≥100）；
  网名 = 前 15 位，密钥 = 第 15–24 位（含校验位）——与对方解析完全一致。展示按 5-5-5-5-5 分组。
  生成时 `value = port + k×65536`（k 随机），保证端口正确且其余位随机。
- **`U/` 码**：21 位，`U/` + 16 位 Base34（4-4-4-4，跳过连字符）+ `% 7 == 0` 校验；
  网名 = `scaffolding-mc-` + 码内第 0–8 位，密钥 = 第 10 位起（与对方实现一致，含连字符）。**码内无端口**，
  加入时要求用户另填端口（借"直连地址"里的端口，未填则明确报错）。
- 我们只解码/编码**字符串格式**，不引入对方任何源码或数据集。

### 5.2 大厅档案（`LobbyTarget`）

| 档案 | 全名 | 密钥 | 覆盖 IP | 加密 | 压缩 | 兼容开关 |
|---|---|---|---|---|---|---|
| PclNext | `pclnext-`+9 | 5 位 | 10.114.114.114 | `aes-gcm`（显式写死） | 不设（none） | 否 |
| CeLegacy | `PCLCELobby`+8 | `PCLCEETLOBBY2025`+2 | 10.114.51.41 | `chacha20` | `zstd` | 是 |
| Terracotta | `terracotta-mc-`+15(小写) | 10 位 | 10.144.144.1 | `chacha20` | `zstd` | 是 |
| CeScaffold | `scaffolding-mc-`+9 | 码内 9 位 | 10.114.51.41 | `aes-gcm` | `zstd` | 是 |

"兼容开关"= `--enable-quic-proxy --enable-kcp-proxy --use-smoltcp --multi-thread`（对方固定加，缺了只是性能/路径差异，加上更贴近）。

### 5.3 会话流程

- `CreateAsync(port)`：读 `LinkInteropTarget`（0/1/2）→ 生成对应档案与邀请码；房主 `-i <档案覆盖 IP>`，白名单仍是 MC 端口。
- `JoinAsync(code)`：先按 pcl-next 码试，再按 CE 数字码、陶瓦码、`U/` 码依次试；成功后按档案参数建网，
  端口转发指向 `档案覆盖 IP : 码内端口`。端口未知（`U/` 码）时用直连地址里的端口，仍无则报错说明。
- 退出时恢复：档案字段清零，不影响下一次（每次建连重新读取设置）。

## 6 回归影响面

- pcl-next 之间：默认"仅 pcl-next"时参数只多了一个显式 `--encryption-algorithm aes-gcm`（等于原默认），行为不变。
- 老版本兼容：本轮不改 pcl-next 码格式，老用户仍可用；反之老版本无法解析 CE/陶瓦码（属新能力）。
- 与 CE 互通：仅能做到"我们加入对方"；对方加入我们受其服务限制（UI 已提示，不夸大）。
- 端口转发、`--listeners`、RPC 探测逻辑不变。

### 10.3 网络层真实握手（EasyTier 2.6.4 本机双实例）

用 CE 那套完整参数起两个 `easytier-core.exe`（`--no-tun --network-name PCLCELobby<8> --network-secret
PCLCEETLOBBY2025<2> --relay-network-whitelist <同网名> --encryption-algorithm chacha20 --compression zstd
--enable-quic-proxy --enable-kcp-proxy --use-smoltcp --multi-thread --private-mode true`）：

| 场景 | 结果 |
|---|---|
| 房主 `-i 10.114.51.41`，加入者 `-p tcp://<本机LAN>:15901` + `--port-forward tcp://127.0.0.1:15902/10.114.51.41:25565` | **成功**：加入者 `easytier-cli peer` 出现 `10.114.51.41/24 cost=p2p tunnel=tcp`，自身获得 `10.114.51.1/24`，日志 `new peer added`、`port forward added local=127.0.0.1:15902 remote=10.114.51.41:25565` |
| 同上但加入者把加密改成 `aes-gcm`（其余全同） | **连不上**：传输层 `new peer connection added` 之后，peer 表始终只有 `Local`，没有 `10.114.51.41` |

结论：① 这套参数（含前缀式网名/密钥、chacha20、zstd、兼容开关）能在两个进程间真实完成握手与端口转发注册；
② 加密算法不一致时确实无法成会话——这正是"加入外部大厅必须自动切对方那套加密"的依据，不能只对齐网名。

### 10.4 环境限制（如实记录，未掩盖）

- 本机 `public.easytier.top:11010` 出站不可达（`Test-NetConnection` 为 False），所以**公共中继路径没验到**；
  上表用的是两个本机进程直连，验的是"握手与会话"这一层，中继可达性属网络环境问题。
- `--use-smoltcp`（CE 默认也开）走用户态协议栈，**不认 127.0.0.1**：本机自连必须用局域网网卡地址，
  否则报 `os error 10049 AddrNotAvailable`；这也意味着本机做互通测试时"直连地址"不能填 localhost。
