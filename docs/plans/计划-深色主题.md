# 计划-深色主题（Windows 主线 · PCL_NEXT_Windows）

> 用户 2026-11-11 指示：为 PCL 开发深色 UI；经确认落在 **PCL_NEXT_Windows（dev.6-Windows）**，
> 形态为 **设置页新增主题项**，路线为 **在现有主题系统上自建深色调色板**。
> 本文件按 `AGENTS.md` §3.2 的八节格式编写。

## 1. 目标

- 在「设置 → 个性化 → 主题」中新增一个可选主题「深色」，选中后立即生效并持久化到 `UiLauncherTheme`。
- 深色下：窗口底、标题栏、侧栏、卡片、输入框、列表项、下拉框、右键菜单、提示气泡、滚动条全部为深色系；
  文字/图标在深色底上保持可读；蓝色强调色保留（PCL 品牌色不丢）。
- 认证口径：切回「龙猫蓝」（0）后与本文档编写前的亮色外观完全一致（不产生亮色回归）。
- 非目标：不实现主题解锁机制，不恢复甜柠青/玄素黑等第 1–14 号主题的真实配色（现状即为空实现，本轮不动）。

## 2. 前置条件与阻塞项

- 基线：`dev.6-Windows` 当前工作树干净（仅 `docs/` 有他人改动时需先确认）。
- 无外部依赖、无联网需求；不涉及上游授权条款（仅 Windows 自用改版，不新增分发通道）。
- 不阻塞：PB3/P4-B、Linux 线、VB 收尾均与本计划正交。

## 3. 现状分析

- `Modules/ModSecret.cs` 的 `ThemeRefresh` 只按 `ColorHue/ColorSat/ColorLightAdjust` 生成 8 级**亮色**色阶，
  完全忽略 `theme` 参数；`ThemeCheckAll`/`ThemeCheckOne`/`ThemeUnlock` 为空实现 → 主题选择实际无效。
- `ColorBrush1..8` 中 5~8 号在亮色下是「浅色底」，但同时被当作**蓝色强调底上的前景**使用
  （`MyExtraButton.xaml:24`、`MyExtraTextButton.xaml:24,29`、`PageDownloadInstall.xaml:345/354/356`、
  `FormMain.xaml:136`）。若直接反转 5~8，这些前景会变成深色 → 必须改用新的 `ColorBrushOnAccent`。
- `ColorBrushGray1..8` 为**静态**资源，`ThemeRefresh` 从不更新，且 69 处用 `StaticResource` 引用可变颜色键
  → 切主题时不会刷新，需改 `DynamicResource` 并纳入刷新。
- 硬编码浅色面：`MyCard.cs:105` 卡片底 `#F5FFFFFF`、`MyMsgText.xaml` 背景 `#FBFBFB`、
  `PageSetupUI.xaml:95` 遮罩 `#DDDDDDDD`、`Application.xaml`/`MySlider.xaml` 弹层 `White` 等。
- 窗口/标题栏底色在 `ThemeRefreshMain` 里按 HSL 亮度 91/48~54 生成，深色需另给一套亮度。

## 5. 改动要点

| Color2 | L=45+adj | L=72 | 悬停/强调文字 |
| Color3 | L=55+adj | L=62 | 主强调（保留蓝） |
| Color4 | L=65+adj | L=76 | 高亮强调 |
| Color5 | L=80 | L=32，sat×0.45 | 弱化文字/浅强调底 |

| Color8 | L=97 | L=14，sat×0.25 | 页面底 |

### 5.2 刷新机制

- `ThemeRefresh` 内：`bool dark = ThemeNow == ThemeDarkId;` 按上表分支计算，随后统一写入
  `ColorBrush*`、`ColorObject*`、`ColorBrushGray1..8`（新增）、`ColorObjectGray1..8`（新增）、语义键。
- `ThemeRefreshMain`：深色时标题栏 HSL 亮度 22/26/22；彩色窗口底 91→15；非彩色 `#12171F`。
- 新增主题项：`MyRadioBox SettingService.Key="UiLauncherTheme" Value="100" Text="深色"`，
  主题网格加一行（`PanLauncherTheme` 高度 90→112）。

### 5.3 资源引用规范化

- 69 处 `StaticResource` 中属于可变色键的全部改 `DynamicResource`（`ColorBrushTransparent`、
  `ColorBrushSemiTransparent` 保持静态：前者恒定透明，后者 alpha=1 无可见差异）。
- 强调底前景：凡 `ColorBrush5..8`/`White` 作为 **Foreground/Fill/Stroke** 且父级底色为 `ColorBrush2..4` 的，
  改 `ColorBrushOnAccent`（已知 7 处，实施时以检索结果为准）。

## 6. 回归影响面

- 主题切换路径：设置页单选、HSL 滑条、启动时 `FormMain` 调用 `ModSecret.ThemeRefresh`。
- 所有引用可变颜色键的控件与页面（列表/下载/实例/设置/联机）。
- 动画：`AaColor(..., "ColorBrushN"/"ColorObjectN")` 读资源起止值，键名不变即不需改。
- 不做测试工程；靠构建 + 统一运行验收（见 7）。

## 7. 验证步骤

1. 增量开发期只做静态验证：
   `dotnet build PCL_NEXT_Windows/pcl-next/pcl-next.csproj -c Release -r win-x64 --self-contained`
   要求 0 错误；产物按 §零 落到 `pcl-next/bin-net10/<代号>/<版本名>-<构建号>/win-x64/`。
2. 全量完成后一次性运行验收（不弹窗式反复试）：
   - 默认启动（龙猫蓝）逐页对比改动前截图，确认无亮色回归；
   - 设置页切「深色」→ 标题栏/侧栏/卡片/输入框/列表/下拉/右键菜单/提示气泡/滚动条均为深色；
   - 下载页开始下载按钮、快捷按钮图标、标题栏文字在蓝底上仍为白字；
   - 重启启动器后深色保持；切回「龙猫蓝」恢复亮色。
3. 判定标准：无「亮块残留」、无「深色字压深色底」，第 5.1 表内资源全部生效。

## 8. 回滚方案

- 本轮改动集中在主题资源与引用方式，回滚 = `git revert` 对应的 `feat(ui): 深色主题` 提交；
- `UiLauncherTheme=100` 若被写入配置，回滚后 `ThemeRefresh` 会把它当普通主题号处理（走亮色分支），
  不会崩溃；必要时在设置页手动切回「龙猫蓝」。
