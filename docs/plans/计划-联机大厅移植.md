## 一、目标

用**零自建服务**的方式恢复 pcl-next 的联机能力，并逐步演进到「邀请码加入 + 房间内玩家列表」的大厅形态：

1. **可验证标准 P1（Phase 1 收口）**：设置页「联机」导航项恢复可见；点击「创建房间」能起 EasyTier、给出邀请码；另一台机器用邀请码能加入并在本地 `127.0.0.1:<port>` 进入同一 MC 服务器；全程**不需要任何 pcl-next 自己的服务端**。
2. **可验证标准 P2**：联机设置页的「节点状态 / 自定义节点」入口可用，节点源来自 `uptime.easytier.cn`（EasyTier 公共节点池）。
3. **可验证标准 P3（可选）**：房间内玩家列表 / 房主名 / 端口协商由房主本机的 ScaffoldingServer 提供（移植 CE `PCL.Core\Link\Scaffolding` 的 Apache-2.0 部分）。
4. **明确不做**：公开房间广场列表（需要中心 API）、纳塔亚克账号体系（需要 OAuth 密钥）、任何对 CE 自建服务 `pcl2ce.pysio.online` 的调用。

## 三、现状分析

### 3.1 已有的旧联机（可直接复用）

`pcl-next\Pages\PageLink\PageLinkMain.xaml(.cs)`（21KB + 61KB）：完整的状态机（创建/加入/加载/完成四态）、邀请码生成与解析、EasyTier 进程管理、`联机模块 CLI.exe` 查 peer、端口转发、崩溃检测、剪贴板邀请码。

`pcl-next\Pages\PageSetup\PageSetupLink.xaml(.cs)`：联机设置页（延迟模式、自定义节点、节点状态、贡献节点）。

`Modules\ModEvent.cs`：`pcl-next://` 协议 / 剪贴板邀请码入口（`PageLinkMain.Join(Arg)`）。

### 3.2 它为什么是坏的（根因链）

1. `PageLinkMain.InitConfig` 第一句就判断 `ModSecret.VersionBranchMain != "Official"` → **开源版直接 throw「开源版无法联网获取配置」**。这是上游刻意切断的。
2. 即使绕过该 throw，后续 `InitPrepareDownload` / `InitLaunch` / `GetTargetPeers` 仍在读 `ModSecret.ServerConfig["Link"][...]`（`EasyTierVersion` / `Downloads` / `Argument` / `DiscoverPeer` / `DiscoverPeerId` / `PeersBlackList`），而 `ServerConfig` 恒为 null → `NullReferenceException`。
3. `Settings.cs` 把联机入口与联机设置页强制隐藏，用户根本看不到入口。

结论：**旧联机不是「需要新功能」，而是「配置源被摘掉了」**。把它改为内置配置是最短路径。

## 五、改动要点

### 5.1 `ModLinkConfig`（新增）

把旧实现需要的字段集中到一个 C# 类，语义与 `ModSecret.ServerConfig["Link"]` 一一对应，便于 Phase 3 之后整体替换：

- `EasyTierVersion = 2642`（v2.6.4，用整数编码便于与现有 `LinkEasyTierVersion` 设置比较）
- `Downloads`：`https://github.com/EasyTier/EasyTier/releases/download/v2.6.4/easytier-windows-{arch}-v2.6.4.zip` + ghproxy 镜像
- `Argument`：EasyTier 基础命令行（`--network-name` 等由调用方拼接）
- `FallbackPeers`：`tcp://public.easytier.top:11010`、`tcp://public2.easytier.cn:54321`、`udp://public.easytier.top:11010`
- `PeersBlackList`：空
- `NetworkNamePrefix`：`pclnext-`（与 CE 的 `ETNetworkNamePrefix` 隔离）
- `MinVersionCode = 0`、`DisableReason = ""`（保留字段语义，便于后续远程开关）

### 5.2 `PageLinkMain`

- `InitConfig`：删「Official 才可联网」的 throw，改为「读内置配置 → 校验不空 → 保留 MinVersionCode / 远程禁用字段的判断（当前恒通过）」。

`_Get_ForcedSettings` 移除两条联机相关强制项。解禁后：`FormMain` 恢复「联机」标签页，`PageSetupLeft` 恢复「联机」导航项（`ItemLink` 已存在，Tag=1）。

### 12.2 关键实现决定（均经实测确认）

1. **监听端口显式声明**：只传端口号会让 EasyTier 顺带占用 +1/+2/+3 端口（实测 host 的 `wg/ws/quic` 落到 40112~40114，与第二个实例撞车）。改为 `--listeners tcp://0.0.0.0:<p>` 与 `--listeners udp://0.0.0.0:<p>` 两条，实测只开这两个监听，无派生端口。
2. **房主固定 IP 与端口白名单**：房主 `-i 10.114.114.114`、`--tcp/udp-whitelist <MC端口>`；加入者 `-d`、白名单 `0`、`--port-forward tcp/udp://127.0.0.1:<本地>/10.114.114.114:<MC端口>`。
3. **就绪判定**：房主用 `easytier-cli node` 成功（即进程可管理）；加入者用 `peer list` 中 `cost != "Local"` 的条目数 ≥ 1（`peer list` 含本机自身，直接数长度会永远为真）。
4. **`--no-tun`**：`app.manifest` 是 `asInvoker`（无管理员），所以走用户态转发，不开虚拟网卡。
5. **下载进度**：多镜像顺序回退，`HttpClient` 流式写入并每 10% 报一次百分比 + 实时速率；单镜像 5 分钟超时，避免「进度条不动但永远不结束」。

### 12.3 实测记录

- 参数集验证（v2.6.4 官方包）：host 启动后 `node` 返回 `ipv4=10.114.114.114/24`、`listeners` 仅 tcp/udp 探测端口、`tcp_whitelist=["25599"]`、`no_tun=true`、`private_mode=true`。
- 直连闭环（同机双实例，绕开公共节点）：加入者 `peer list` 出现 `cost=p2p` 的房主条目（lat 0.19ms），随后向 `127.0.0.1:<转发端口>` 建立 TCP 连接**成功**——证明白名单 + 端口转发 + overlay IP 这条链路可用。
- **公共节点不可达（重要）**：2026-11-14 本机实测 `tcp://public.easytier.top:11010`、`udp://public.easytier.top:11010`、`public2.easytier.cn:54321`、`etnode.zkitefly.eu.org:11010` 全部连接超时（TCP 探测 6~7 s 无响应；解析出的 47.91.170.222 / 47.76.127.217 / 8.218.208.240 / 110.42.53.117 同样不通），而同期 `mc.hypixel.net:25565` 可正常连通，说明不是本机端口封锁，而是这批公共节点当前不可用或对本地区不可达。
  因此补了两条退路：① 设置里的 `LinkCustomPeer` 自定义节点优先级高于内置节点；② 新建房会给出「同网络直连地址 IP:端口」，加入页新增「直连地址（可选）」输入框，公共节点失效时可用它直连（跨公网仍需可达的节点或端口映射）。
- 下载链路：GitHub 直连实测约 113 KB/s（32 MB 需 ~5 分钟），已追加 `ghfast.top`、`gh.llkk.cc` 两个加速镜像作为备选。
