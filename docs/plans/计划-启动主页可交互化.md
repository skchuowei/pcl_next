# 计划：启动主页从「内容看板」升级为「可操作工作台」

> 状态：**规划（未实施）** ｜ 提出 2026-11-14 ｜ 基线：`dev-Windows` 工作区
> 关联文档：`docs/bugscan/G1-启动主页.md`（启动主页侧已知缺陷留痕）、
> `docs/plans/计划-实例信息卡.md`（实例设置「概览」页信息卡，已落地，本轮复用其数据口径）
> 本计划只覆盖**启动页右侧**（`PageLaunchRight`）；左侧版本选择/启动按钮不动。

## 1. 目标与验收

### 1.1 现状（一句话）

启动页右侧是一块**只读看板**：`PanCustom` 里放的是自定义主页 XAML（来源由 `UiCustomType` 决定：0 关闭 /
1 本地 `PCL\Custom.xaml` / 2 联网 / 3 预设共 25 种），下面是启动日志卡。实例相关的信息与入口全部在
「版本设置」子页面里，主页既看不到当前实例状况，也没有任何可点的操作项（`UiCustomType` 默认 0 时
右栏事实上只剩一张启动日志卡）。

### 1.2 目标形态

在 `PanCustom` **之上**插入一块内置「工作台」，**只在已选中实例时出现**，内容为「摘要 + 动作」而不是明细：

```
┌ 当前实例 ───────────────────────────────────────┐
│ [图标]  1.20.1-Fabric                       [切换] │
│         MC 1.20.1 · Fabric 0.15.11                 │
│  Mod 42（禁用 3） · 存档 7 · 已启动 36 次 · 2 天前  │
│  [继续上次存档]  [存档列表]  [实例设置]  [文件夹]   │
└──────────────────────────────────────────────────┘
┌ 快速进入存档 ─────────────────────────────────────┐
│ [图标] 生存世界          2 天前               [▶]  │
│ [图标] 建筑测试          5 天前               [▶]  │
│ [图标] 空岛生存          12 天前              [▶]  │
│ 共 7 个存档                              [全部存档] │
└──────────────────────────────────────────────────┘
     （以下为原有的 PanCustom 自定义主页卡片，位置与内容不变）
     （再下方为原有的 PanLog 启动日志卡，位置不变）
```

两条核心诉求对应关系：

| 用户诉求 | 落地形态 |
|---|---|
| **显示实例信息** | 「当前实例」卡的一行摘要（实例名 / MC 版本 / 加载器及版本）+ 一行统计（Mod、存档、启动次数、上次游玩） |
| **快速进入存档** | 「快速进入存档」卡：最近 3 个存档一键直达（`--quickPlaySingleplayer`），以及「存档列表 / 打开存档文件夹」兜底入口 |

### 1.3 可验证标准（逐条可判定）

1. 未选中实例（`McInstanceSelected == null`）时，两块内置卡整体隐藏，主页与改造前**完全一致**；
2. 选中实例后，摘要行的 MC 版本 / 加载器版本与实例 JSON 解析结果一致（与概览页「实例信息」卡同一口径）；
3. Mod 数、存档数与资源管理器中 `PathIndie\mods\`、`PathIndie\saves\` 的实际数量一致（禁用 Mod 单独计数）；
4. 1.20+ 实例点击存档行 → 游戏启动后**直接进入该存档**（不是主菜单）；1.20 以下实例点击 → 提示不支持并改为普通启动；
5. 自定义主页三种来源（本地 / 联网 / 预设）在插入内置卡后仍正常渲染，位置不被抢占，`F5`/刷新行为不变；
6. 新增设置项 `UiHomeWorkspace` 关闭后，主页行为与当前版本完全一致（像素级回归）；
7. 全新构建 0 个 C# 编译错误（exe 被运行中实例锁定除外）。

## 3. 现状分析

### 3.1 主页右栏结构（`PageLaunchRight.xaml:8-20`）

```
MyScrollViewer
└─ StackPanel PanMain (Margin 25,25,25,10)
   ├─ MyHint  PanHint     ← 快照版提示，按渠道/等级显示
   ├─ StackPanel PanCustom ← 自定义主页内容（LoadContent 动态填充，可空）
   └─ MyCard  PanLog      ← 启动日志（仅 Debug 模式可见）
```

插入点明确：**`PanHint` 之后、`PanCustom` 之前**。整块宽度随窗口自适应，`StackPanel` 纵向堆叠，追加卡片不影响既有布局。

### 3.2 自定义主页渲染管线（不可破坏的部分）

`PageLaunchRight.xaml.cs:359-397` `LoadContent`：

- 内容先经 `ModMain.ArgumentReplace(Content, XmlEscape)` 做变量替换；
- 强制剥离全部 `xmlns` 声明，再包一层固定命名空间（`local=clr-namespace:PCL`、`core=MeloongCore`…）；
- 经 `ModBase.GetObjectFromXML` 实例化，类型/成员黑名单在 `ModBase.cs:1356-1367`
  （禁 `WebBrowser / Frame / MediaElement / XamlReader / Window / SettingService` 等，禁 `Code / FactoryMethod / Static`）；
- 有内容哈希门控（`LoadedContentHash`）+ 联网缓存（`PathTemp Cache\Custom.xaml`）+ 10 分钟重载超时。

→ 结论：内置工作台**必须完全绕开这套管线**（不塞进 `PanCustom`、不复用 `OnlineLoader`、不参与哈希门控），
否则每次切换实例都会触发自定义主页重载或缓存失效。

### 3.3 实例与存档能力现状

| 能力 | 位置 | 结论 |
|---|---|---|
| 实例信息行装配 | `PageInstanceOverall.xaml.cs:107-201`（`RefreshInstanceInfo` + `AddInfoRow` + `AddLoaderRow`） | 已有完整实现，但绑死概览页实例（`PageInstanceLeft.Instance`），**主页复用需抽公共方法**，否则会形成第二份实现（违反 AGENTS §0.3.1「同一规则只能一处真源」的教训） |
| 存档唯一入口 | `PageInstanceOverall.xaml.cs:388-393` `BtnFolderSaves_Click` | 只打开文件夹，无列表、无直达 |
| 启动参数拼装 | `ModLaunch.cs:1525-1555` | `List<string>` 逐项拼接；含空格/`&|<>^` 自动加双引号（`:1544-1547`），中文原样传递 → 存档名带空格/中文安全 |
| 服务器直连 | `ModLaunch.cs:1897-1928` | 用 `ReleaseTime > 2023-04-04` 判 `--quickPlayMultiplayer`；同判据可直接复用于单人 quickPlay |
| 启动选项 | `ModLaunch.cs:29-50` `McLaunchOptions` | 现有字段：`ServerIp / SaveBatch / Instance / ExtraGameArgs`，无单人存档字段 |

### 3.4 已知缺陷留痕（本计划不修，但需规避）

`G1-启动主页.md` 记录：联网主页下载完成后的刷新判定在 `LoadedContentHash` 为 null 时被抑制
（`PageLaunchRight.xaml.cs:312`）、后台线程读 hash 未加锁（`:312/367-369`）。本轮新增逻辑
**不得依赖 `LoadedContentHash`**，也不得在 `OnlineLoaderSub` 里插入调用。

## 4. 设计取舍（三个明确决定）

### D1：双轨制，内置工作台与自定义主页**并存**，不替换

不把实例信息塞进自定义 XAML 体系（那会让 25 个社区预设全部需要改写），也不关掉自定义主页。
内置卡固定在最上方，自定义内容顺延；用设置项 `UiHomeWorkspace` 提供**一键回到旧形态**。

> 理由：默认 `UiCustomType = 0`（`PageSetup\Settings.cs:48`），绝大多数用户右栏本就是空白，
> 内置卡默认开启是"填空白"而非"抢版面"；而重度自定义用户有开关可退。

### D2：主页只放**摘要 + 动作**，不放明细列表

概览页那种「启动次数 / 整合包版本 / MC / 各加载器各占一行」的竖列表不适合首屏（要占 6-8 行高）。
主页压成：

- **1 行识别**：实例名（`MyListItem`，图标复用 `Instance.Logo`，与版本选择页同款渲染，支持 pack URI / 本地 png）；
- **1 行统计**：`Mod 42（禁用 3）· 存档 7 · 已启动 36 次 · 2 天前` 单行 TextBlock，用 `·` 分隔；
- **1 行动作**：最多 3 个文字按钮 + 1 个图标按钮，超出的收进「更多」。

分工写进注释：**主页 = 摘要 + 入口，概览页 = 明细 + 管理**。

### D3：存档先「直达」后「管理」，本轮不做存档管理页

真正的存档管理（重命名 / 复制 / 删除 / 单存档备份）需要 NBT 写入、存档占用判定、zip 打包，
体量与「联机大厅移植」同级，单独立项。本轮只做三件事：

1. 最近存档**直达**（`--quickPlaySingleplayer`）；
2. 存档**列表 + 打开文件夹**（读目录，只读）；
3. 「继续上次游玩」（取最后修改/最后游玩最大的存档，一键直达）。

## 7. 改动要点

### 7.1 XAML 结构（`PageLaunchRight.xaml`）

在 `PanHint` 之后插入：

```xml
<StackPanel x:Name="PanWorkspace" Visibility="Collapsed">
    <local:MyCard Margin="0,0,0,15" Title="当前实例" x:Name="PanInstance">
        <StackPanel Margin="25,30,25,15">
            <ContentControl x:Name="PanInstanceHead" />
            <TextBlock x:Name="LabInstanceStats" Margin="0,8,0,0" FontSize="12.5"
                       Foreground="{DynamicResource ColorBrushGray2}" TextWrapping="Wrap" />
            <WrapPanel x:Name="PanInstanceActions" Margin="0,14,0,0" />
        </StackPanel>
    </local:MyCard>
    <local:MyCard Margin="0,0,0,15" Title="快速进入存档" x:Name="PanSaves">
        <StackPanel Margin="25,30,25,15">
            <WrapPanel x:Name="PanSaveList" />
            <Grid Margin="0,10,0,0">
                <TextBlock x:Name="LabSaveSummary" VerticalAlignment="Center" FontSize="12.5"
                           Foreground="{DynamicResource ColorBrushGray2}" />
                <local:MyButton x:Name="BtnSavesAll" HorizontalAlignment="Right" Height="30" MinWidth="110"
                                Padding="13,0" Text="全部存档" />
            </Grid>
        </StackPanel>
    </local:MyCard>
</StackPanel>
```

要点：

- 两张卡都用 `MyCard`（标题由控件自绘，不需要额外标题 TextBlock）；
- 卡片内边距统一 `25,30,25,15`（与概览页 `PanInfoCard` 一致，`MyCard` 标题占顶部 30px）；
- 动作条用 `WrapPanel` 而非 `Grid`，窄窗口下按钮自动换行，不做横向压缩；
- 存档行用 `MyListItem`（`Title`=存档名，`Info`=时间，`Logo`=存档 `icon.png` 的绝对路径，
  `Height=36`），右侧追加一个 `MyIconButton`（`Logo=播放图标`）作为「直入」；整行也可点击，两处同一动作。

### 7.2 实例摘要装配（`PageLaunchRight.xaml.cs`）

```
RefreshWorkspace():
  1. Instance = ModMinecraft.McInstanceSelected
  2. Instance == null → PanWorkspace = Collapsed；return            // 与旧形态完全一致
  3. PanWorkspace = Visible
  4. 清空 PanInstanceHead / PanInstanceActions / PanSaveList
  5. 头部：new MyListItem { Title=Instance.Name, Info=$"{MC} · {Loader}", Logo=Instance.Logo, IsHitTestVisible=false }
  6. 统计行（单行文本）：
       ModCount    = PathIndie\mods\*.jar|*.zip 文件数
       ModDisabled = PathIndie\mods\.disabled\ 文件数
       SaveCount   = PathIndie\saves\ 下含 level.dat 的目录数
       LaunchCount = ReadIni(PathVersion+PCL\Setup.ini, "VersionLaunchCount", 0)
       LastPlay    = P0: max(saves\*\level.dat 的 LastWriteTime)；P1: max(LastPlayed)
                    → 格式化为「2 天前 / 今天 / 从未游玩」
  7. 动作按钮（最多 3 个文字按钮 + 1 个图标）：
       [继续上次存档] → 有存档才显示，见 7.4
       [存档列表]     → 展开/收起 PanSaves 的完整列表（P0 默认只列 3 条）
       [实例设置]     → PageChange(InstanceSetup, InstanceOverall)
       [文件夹 icon]  → OpenExplorer(Instance.PathVersion)
       [切换] 文字按钮固定在头部行右侧 → PageChange(InstanceSelect)
```

加载器文本规则（与概览页一致，避免两套口径）：

- `McVersion.VanillaName` 作版本段；
- 依 `ModLoaders` 标志依次取 `Forge / NeoForge / Fabric / LiteLoader`，值取 `ModLoaderVersions[loader]`，
  缺值写「未知版本」；
- `OptiFine` 非空时追加一段；
- 单行最多显示 3 段，超出以「等 N 项」收尾（避免窄窗口撑爆）。

**共享抽取**：把 `PageInstanceOverall` 里的「取 MC 版本段 / 取加载器段」抽成
`ModMinecraft.McInstance` 上的静态方法（如 `BuildVersionSummary(instance)` 返回 `(string mc, string loader)`），
概览页与主页同时调用，杜绝两份拼装逻辑。

### 7.3 存档枚举（新增 `ModSave.cs`）

```
class SaveEntry {
    string FolderName;   // saves\ 下的目录名，即 quickPlay 参数值
    string FullPath;
    string DisplayName;  // P0=FolderName；P1=NBT LevelName
    string IconPath;     // 访问过才有 icon.png
    DateTime LastPlayed; // P0=level.dat 修改时间；P1=NBT LastPlayed
    long SizeBytes;      // P1 才有（NBT Size，单位：游戏刻折秒）
}

EnumerateSaves(McInstance instance):
  根 = (instance.PathIndie ?? McFolderSelected) + "saves\"
  遍历一级子目录；含 level.dat 才算有效存档（排除 _backup / 空壳目录）
  按 LastPlayed 倒序，最多返回 N 条（列表全量，卡片只取前 3）
```

- 只读，不写、不移动、不删除任何存档文件；
- 目录不存在 → 返回空列表并 `DirectoryUtils.Create`（与概览页「存档文件夹」按钮行为一致，可创建）；
- 单个目录读取异常只跳过该条，不整体失败（`try/catch` 逐条包裹）。

### 7.4 `--quickPlaySingleplayer` 直入存档（`ModLaunch.cs`）

1. `McLaunchOptions` 增加：

```csharp
/// <summary>启动后直接进入的单人存档目录名（saves\ 下一级，不含路径）。
/// 默认 null。与 ServerIp 同时设置时以本项优先。</summary>
public string SingleplayerSave = null;
```

2. `McLaunchArgumentsGame()` 中，紧跟现有「自动进入服务器」之前插入：

```csharp
if (!string.IsNullOrEmpty(CurrentLaunchOptions.SingleplayerSave))
{
    if (McInstanceSelected.ReleaseTime > new DateTime(2023, 4, 4))
    {
        Args.Add("--quickPlaySingleplayer");
        Args.Add(CurrentLaunchOptions.SingleplayerSave);   // 空格/中文由 :1544-1547 自动加引号
        if (!string.IsNullOrEmpty(Server)) McLaunchLog("同时指定了存档与服务器，已忽略服务器直连");
    }
    else
    {
        ModMain.Hint($"版本 {McInstanceSelected.Version.VanillaName} 不支持直接进入存档，已改为普通启动", ModMain.HintType.Red);
    }
}
```

3. 调用侧（主页存档行点击）：

```csharp
ModLaunch.McLaunchStart(new ModLaunch.McLaunchOptions {
    Instance = ModMinecraft.McInstanceSelected,
    SingleplayerSave = save.FolderName
});
```

4. 互斥规则：`SingleplayerSave` 非空时**不传** `--quickPlayMultiplayer`（二者同传会被游戏忽略其一）；
5. 降级行为：存档目标不存在（用户删了存档）时，MC 自身会停在标题界面的世界选择，**不视为崩溃**，主页不额外拦截。
