# 计划-整合包备份与还原（实例隔离版）

> 立项时间：2026-11-14　分支：`dev-Windows`　当前代号：`alpha`（构建号见 `obj/pcl-build.small`）
> 依据：用户 2026-11-14 给出的「多实例隔离下的整合包备份与还原体系」修正方案，要求按该方案实现。
> 本文件为本次大改动的唯一计划真源；实现细节与偏离均回写到本文件。

---

## 1. 目标

为 PCL Next（Windows / `dev-Windows`）补齐**实例级**的整合包备份与还原能力，可验证标准如下：

1. 每个实例都有**自己的**备份空间，落在该实例目录内（`versions\<实例名>\backups\`），删除 / 移动实例时备份跟随，不与其他实例共用。
2. 支持五类备份：**初始基准备份（initial）**、**手动完整 zip（full-zip）**、**整合包备份（modpack）**、**增量备份（incremental）**、**还原前兜底（pre-restore）**。
3. 整合包安装完成后自动生成该实例的初始基准包并锁定。
4. 还原操作只允许「当前实例的备份 → 当前实例」，且还原前按 10 分钟阈值自动兜底。
5. 备份页明确显示当前实例；切换实例后列表自动刷新；文件名可辨识实例、类型、时间。
6. Release 编译 0 错误，产物落在 `pcl-next\bin-net10\<代号>\<版本名>-<构建号>\win-x64\`。

## 2. 前置条件与阻塞项

- 依赖 `MeloongCore` 的 `FileUtils` / `DirectoryUtils` / `PathUtils`、`ModLoader.LoaderTask` 进度框架、`MyListItem` / `MyCard` / `MyButton` 控件，均已存在，无外部依赖。
- 无阻塞项。实例复制（clone）功能在本启动器中**不存在**，故「复制实例时可选复制备份」一条本期不做（见 §4 边界）。

## 3. 现状分析

- 实例模型：PCL 的「实例」= `McInstance`，物理目录为 `McFolderSelected + versions\<Name>\`（`PathVersion`）；`PathIndie` 由 `VersionArgumentIndieV2` 决定——开启隔离时等于 `PathVersion`，关闭时等于全局 `.minecraft` 根。
- 整合包安装：`Modules\Minecraft\ModModpack.cs` 已支持 CurseForge / Modrinth / HMCL / MMC / MCBBS / 压缩包六类安装，安装时统一写 `PCL\Setup.ini` 的 `VersionArgumentIndieV2=True`（即整合包实例默认隔离）。
- 现状缺口：工程内**没有任何**备份相关代码（`Backup|Snapshot|Archive|Zip` 检索为空），实例删除直接 `DirectoryUtils.Delete(PathVersion)`，不会提示备份。
- 相关既有能力：导出整合包（`PageInstanceExport`）只导出分发用的整合包，不是本地快照；不能替代备份。

## 5. 改动要点

### 5.1 目录与隔离（硬约束）

```
versions\<实例名>\                      ← PathVersion（实例根）
└── backups\                            ← 该实例专属，禁止全局共用
    ├── initial\                        ← 初始基准备份（导入整合包后自动生成，锁定）
    ├── manual\
    │   ├── full-zip\                   ← 手动完整 zip
    │   ├── modpack\                    ← 手动整合包备份（含存档/选项/服务器列表）
    │   └── incremental\                ← 增量备份（必须存在实例内基准）
    └── pre-restore\                    ← 还原前兜底
```

- 备份根永远 = `Instance.PathVersion + "backups\"`；内容根 = `Instance.PathIndie`。
- 实例未开启隔离时 `PathIndie` 是全局根，此时额外排除 `versions\`、`assets\`、`libraries\`，避免把别的实例一起打包；备份仍只写回本实例 `PathVersion`。
- 备份文件命名：`<实例名>_<类型>_<yyyyMMdd-HHmmss>[_<备注>].zip`；同名冲突追加 `-2`、`-3`。
- 类型标记：`初始` / `完整` / `整合包` / `增量` / `还原前`。

### 5.2 清单（sidecar）

每个 zip 旁边写一份同名 `.json`：

```json
{
  "Version": 1,
  "Kind": "full-zip",
  "Instance": "实例名",
  "CreatedAt": "2026-11-14T15:03:22+08:00",
  "Remark": "",
  "Locked": true,
  "Base": null,
  "Files": [ { "p": "mods/xxx.jar", "s": 1234, "t": "2026-11-14T12:00:00" } ],
  "Deleted": []
}
```

- `Files` 记录快照时刻的文件清单（相对路径、字节数、修改时间），用于增量对比与还原校验。
- 增量包 `Base` 指向基准 zip 文件名，`Files` 只记变更项，`Deleted` 记被删除的相对路径。
- 清单缺失（老包 / 手工放入）时按「仅 zip」降级：可还原、不可作增量基线。

### 5.3 备份内容口径

- **完整 zip / 增量 / 初始基准备份**：内容根下全部文件（`BackupScope.Full`），排除 `backups`、`logs`、`crash-reports`、`caches`、`cache`、`.cache`、`.fabric`、`.mixin.out`、`avatar-cache`、`cosmetic-cache`、`downloads`、`PCL`、`structureCacheV1`，以及 `*.log`、`hs_err_pid*.log`。
  **初始基准取全量而非白名单**：它是增量链的基线，只有全量快照才能保证「基线 ∪ 增量」可完整复原实例；同时它也是「装完整合包那一刻」最可靠的整目录时间点。
- **整合包手动备份**（`BackupScope.Modpack`）：只取整合包相关与运行必需项——`mods`、`config`、`defaultconfigs`、`kubejs`、`scripts`、`saves`、`resourcepacks`、`shaderpacks`、`options.txt`、`optionsof.txt`、`servers.dat`、`iris.properties`。强制包含 `saves`/`options.txt`/`servers.dat`（存在时）。
- 两类都从**已安装完成的实例**提取，禁止直接复用原始下载的整合包文件。

### 5.4 触发规则

| 触发点 | 行为 |
|---|---|
| 整合包安装完成 | 在该实例 `backups\initial\` 生成初始基准包，`Locked=true`，UI 不可删除 |
| 手动「新建完整备份」 | 写入 `backups\manual\full-zip\` |
| 手动「新建整合包备份」 | 写入 `backups\manual\modpack\` |
| 手动「新建增量备份」 | 以该实例内**最近的完整基准**（`Initial` / `FullZip` / `Incremental`，且 `Scope=Full` 且清单非空）为基准；无基准则按钮禁用并提示「请先做一次完整备份」 |
| 任意还原前 | 取该实例 `manual\full-zip` 最新一份：距今 ≤ 10 分钟 → 生成 `完整` 兜底；> 10 分钟 → 生成 `整合包` 兜底，并清理 `pre-restore` 中超过 10 分钟的完整 zip 兜底 |
| 实例删除 | 提示该实例下所有备份将一同删除（二次确认后随实例目录删除） |

### 5.5 还原语义

- 完整 / 初始：清空内容根下「除排除目录与 `backups` 外」的全部文件与目录，再解压 zip；`backups` 目录永不清理（否则还原会把兜底包自己删掉）。
- 整合包备份（`Scope=Modpack`）：只清空白名单目录与白名单根文件，再解压；其余文件保留。
- 增量：先递归还原其基准链（完整快照），再覆盖变更文件、删除 `Deleted` 列出的文件；基准缺失或链成环时直接报错，不尝试跨实例找基准。
- 解压自带路径防护：拒绝含 `..` 或解析后越出内容根的条目，跳过首段为受保护目录（`backups` 等）的条目。
- 还原前检查 `McInstanceLock`，实例正在安装 / 运行则拒绝。
- 还原结束提示「已还原到…」，重置该实例设置缓存并强制刷新版本列表（`McInstanceListLoader`）。

### 5.6 UI

`PageInstanceBackup`（实例设置第 7 个子页）顶部固定显示「当前实例：XXX」与备份目录；卡片内为操作按钮 + 分组列表；每行右侧三个图标按钮：还原、备注、删除（初始基准无删除）。创建备份前先弹一次「备份备注」输入框（可留空，取消则中止），备注直接进入文件名与清单；创建 / 还原均走 `ModLoader.LoaderTask` 进任务栏（同名任务已在跑时跳转任务管理页），进度按字节计算，支持取消。

## 6. 回归影响面

- 侧栏页序号必须与 `PageSubType` 枚举一致（`FormMain` 用 `PanItem.Children[(int)SubType]`），新增项只能追加在末尾。
- 整合包安装流程新增末步加载器：确认五类安装仍能完成、`LoaderCombo` 权重不被压低、失败时不影响主流程（初始备份失败仅记日志不阻断安装，取消会正常向上传递）。
- 实例删除：新增提示不改删除语义；不改变 `PathVersion` 删除范围。
- 未隔离实例的完整备份会包含全局存档等数据（属预期，需在 UI 文案说明）。

## 7. 验证步骤

1. 基线：`dotnet build pcl-next\pcl-next.csproj -c Release -r win-x64`（改动前先跑，确认 0 错误；**必须带 RID**，否则被 `Directory.Build.props` 的运行环境护栏拦下）。
2. 改动后同命令编译，判定标准：0 错误；警告数不高于基线。
3. 构建产物核对：`dotnet build ... -getProperty:OutputPath` 落在 `pcl-next\bin-net10\Alpha\<版本名>-<构建号>\`（RID 段为 `win-x64`）。
4. 手工冒烟（有真实实例时）：
   - 进入实例设置 → 备份页，确认顶部实例名与列表为空态；
   - 新建完整备份 → 任务栏出现进度 → 列表出现「完整」条目，文件名含实例名与时间；
   - 修改实例内一个文件后新建增量备份 → 条目显示基准名；
   - 还原完整备份 → 先出现 `还原前` 兜底条目，随后内容回滚；
   - 删除实例 → 弹窗包含备份删除提示。
5. 无实例环境时以「编译 + 静态核对 + 备份目录结构单测式手工验证（用临时目录构造 ModBackup 调用）」替代，并在发布说明中标注未真机验证项。

## 8. 回滚方案

- 代码回滚：`git revert <本次提交>` 即可，新增文件整体移除，无数据迁移。
- 数据侧：备份目录只新增不修改既有实例文件；若用户希望彻底清除，删除对应实例 `backups\` 目录即可（不影响游戏本体）。
- 若初始备份导致安装流程异常：删除 `ModModpack.cs` 中 `AppendInitialBackupTask` 调用即可降级，`ModBackup.cs` 可保留。
