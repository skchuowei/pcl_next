# 计划-构建号：每次编译 +0.01

> 立项：2026-11-14，用户指示「改 build 算法，每次编译都要加 0.01」。
> 经确认，落到「编号 = 提交数 + 本机累计编译次数」这一层（选项 A），
> 不改目录树形状、不改三段树路径规则。

## 1. 目标

1. 同一提交下**反复编译**也能得到不同的构建号（每次 +0.01），不再「同号不同物」。
2. 提交维度保留：提交数仍参与编号，跨机器可核对「这份产物包含到哪个提交」。
3. 三个落点（**目录名 / AssemblyInformationalVersion / 制品文件名**）永远同源，
   不允许出现「目录是 1.22、exe 里写着 1.23」。
4. 发布构建仍要求双 RID 同号、且与 tag 对应的纯提交语义一致。

## 2. 前置条件与阻塞项

- MSBuild **属性求值期不能执行 git / 脚本**，`OutputPath` 偏偏在该阶段定死，
  因此「每次编译换号」只能靠**缓存文件**（`obj\pcl-build.small`）提前落盘。
- 一次构建里 `Get-BuildSmallVersion.ps1` 会被调用 3～4 次（Build.ps1、编译目标、
  制品复制、钩子），递增必须**幂等**，否则一次构建会加好几个 0.01。
- 无阻塞项。

## 3. 现状分析

原算法 `BuildSmall = 提交数 × 0.01`（`scripts\Get-BuildSmallVersion.ps1`），
只数提交。2026-11-13 已补 `BuildContentId` / `BuildUuid` 解决「同号不同物」的**可区分性**，
但编号本身仍不变：同一提交连编三次，三个产物都叫 `1.22`，目录也同名（互相覆盖）。
用户要求的是**编号自身**每次编译 +0.01。

## 5. 改动要点

### 5.1 编号公式

```
BuildSmall        = (提交数 + 本机累计编译次数) × 0.01，写 M.mm（满 100 进 1）
BuildSmallNumber  = 提交数 + 编译次数（比较新旧只认它）
提交数            = 继承基数 + 自基线以来提交数（原逻辑不变）
编译次数          = pcl-next\obj\pcl-build.seq（单行整数，obj\ 已忽略）
```

### 5.2 递增时机（关键设计）

**在构建成功结束后**递增，而不是开始时：

- 目录名由求值期读取的缓存决定；编译中途改缓存 → 目录与产物内标识脱钩。
- 结束时递增 = 本次构建三处落点仍读同一份缓存，写回的是**下一次编译**的编号。
- 计数只在 `PclBuildSeqBump` 目标里 +1，一次构建一次，天然幂等。
- 构建失败不递增（失败的编译不该占号）。

### 5.3 发布构建

`release.yml` 的 x64 / arm64 两次 publish 都带 `-p:PclNoBump=true`：
双 RID 必须同号，且发布号回到纯提交语义（与 tag 对齐）。
`Directory.Build.props` 检测到 `PublishProfile` 时也会自动置 `PclNoBump=true`，
并在制品命名步骤**断言**两个 exe 的 ProductVersion 前缀一致。

### 5.4 制品命名

`Copy-VersionedArtifact.ps1` 改为读 exe 自身的 `ProductVersion`（形如
`1.23.gaa500fa.c30d669c84eb1.dirty`）取 `M.mm`，读不到才退回脚本取值。
这样即使缓存已被预置成下一个号，制品名仍与 exe 内标识一致。

## 6. 回归影响面

- **目录数量**：同一提交反复编译会各占一个目录（这是本需求的目的），
  本地需要定期按 §0.2 / §七 清理散装产物；`ReleaseArtifacts` 不受影响。
- **提交信息**：`Build:` 行数值会随本机编译次数增大（钩子读取 `pcl-build.seq`），
  仍是「本次提交那一刻的编号」，与下一次构建编号衔接。
- **CI**：runner 无 `obj\` 缓存 → 编译次数从 0 起算，发布编号与 tag/提交数严格对应；
  本地号会领先 CI，属预期（两套编号本就不可跨机器比较，§5.2.1 已声明）。
- **老产物**：`ProductVersion` 里没有 `.dirty` 或格式不符时按回退逻辑处理，不影响运行。

## 7. 验证步骤

1. `.\scripts\Get-BuildSmallVersion.ps1 -Json` → `Seq=0`、`BuildSmall=1.22`（提交 122）。
2. `.\scripts\Get-BuildSmallVersion.ps1 -BumpSeq` → `seq=1`、缓存 `1.23`，再查询得 `1.23`。
3. `.\scripts\Build.ps1` → 目录 `2.100.0.7-1.23\win-x64`，exe 的 ProductVersion 前缀 `1.23`，
   构建成功后缓存变 `1.24`（seq=2）。
4. 再来一次 `Build.ps1` → 目录 `-1.24`，ProductVersion `1.24`，缓存 `1.25`。
5. `-p:PclNoBump=true` 构建 → 编号不前进。
6. 制品名与 exe ProductVersion 前缀一致。

## 8. 回滚方案

- 回滚 = 还原本轮提交；删除 `obj\pcl-build.seq` 即回到纯提交口径（编号可能回落 0.0x 个位数，
  属回滚预期）。
- 已产出的 exe 内编号在编译期已固化，不受回滚影响。
