# pcl-next 联机大厅使用协议

> 版本：v1.1（2026-11-27 修订：**全面禁止商业使用**；**互通实现必须开源**）
> 发布方：pcl-next 项目（PCL2 的第三方修改版，对外名 `pcl-next`）
> 适用范围：pcl-next 联机大厅的邀请码、房间网络、大厅协议（下称「next 协议」）、准入网关，以及围绕它们提供的任何实现与互通能力。
> 关联文档：《Next协议介绍.md》《Next协议规范.md》《Next协议接入指南.md》

## 0\. 一页看懂（摘要）

* **允许任何人免费使用联机大厅**，不需要申请、不需要授权码。
* **允许其他启动器、工具、服务读取并使用 next 协议**，也**允许复刻（独立重新实现）**，并与 pcl-next 房间双向互通。
* **禁止任何形式的商业使用**：不得售卖、订阅、广告变现、付费捆绑，也不得用于企业内部商业运营（详见 3.1）。
* **互通实现必须开源**：只要你对外提供与 next 互通的程序，源码就必须公开、可自由获取（详见 4.5）。
* 你必须做到五件事：**不冒充官方、不绕过准入、不采集他人数据、不把房间里拿到的文件再分发、不闭源做互通**。
* 联机大厅**没有中心服务器、没有账号体系**：房间由房主自己的电脑提供，成员之间通过 EasyTier 组网直连。

## 1\. 定义

|术语|含义|
|-|-|
|**联机大厅**|pcl-next 提供的「建房 → 分享邀请码 → 他人加入 → 进游戏」整套功能，由房主端与加入端两侧程序组成。|
|**next 协议**|联机大厅的通信协议族，包含三层：承载层（EasyTier 虚拟局域网）、控制面（Scaffolding 大厅服务）、准入面（Gate 网关），以及可选的联机包直传数据面。|
|**房主**|在本机创建房间、运行大厅服务（Scaffolding / 网关）并提供 Minecraft 服务器的人。|
|**成员 / 加入者**|用邀请码进入他人房间的人。|
|**邀请码**|形如 `K7M3Q-XB4T9-3fa8c1d0` 的字符串，同时充当房间地址与网络密钥；开启安全模式的房间会多一个 `-S` 尾段。|
|**准入网关（Gate）**|房主侧的 TCP 准入服务：只有先在控制面完成登记、拿到一次性 ticket 的成员，才能通过挑战-应答进入并转发到房主的 MC 端口。|
|**第三方实现**|非 pcl-next 官方代码、但遵循 next 协议的程序（含其他启动器、机器人、脚本、服务端工具）。|
|**互通**|第三方实现能够与 pcl-next 的房主或加入端在同一房间内完成协议交互，并正常进服。|

## 2\. 服务性质与边界

1. **点对点、无中心服务器。** 联机大厅不提供房间目录、不做账号登录、不做流量中转；房间的可达性取决于房主与成员各自的网络环境，以及 EasyTier 公共/自建节点的可用性。
2. **房主即服务提供者。** 房间由房主电脑上的进程提供。房主关闭程序、退出房间或更换邀请码，房间即失效。
3. **EasyTier 是独立第三方组件。** 本协议只约定「如何用 EasyTier 组网」（网络名、密钥、主机名、端口白名单与转发），不改变 EasyTier 自身的许可证与使用条款；使用 EasyTier 时须同时遵守其项目条款。
4. **Minecraft 服务器本身不在本协议范围内。** 成员进服后的游戏行为、服务器规则、存档与内容版权，由房主与玩家自行约定。
5. **互通不等于同源。** 与 PCL2-CE、陶瓦（Terracotta）等启动器的互通，仅建立在邀请码格式与主机名约定的字符串层面；本协议不涉及、不复制、不模拟对方的源码、账号体系与中心大厅服务。

## 3\. 使用许可（仅限非商业）

在你遵守本协议的前提下，pcl-next 项目授予你**全球范围、免费、非独占、不可转让、可撤销（仅限违约情形）**的许可：

1. 使用联机大厅功能建房、加入、进服；
2. 读取、分析、文档化 next 协议的线格式与行为；
3. **在自己的程序中实现（复刻）next 协议**，包括房主端与加入端；
4. 让你的实现与 pcl-next 的房间**双向互通**（你的加入端进 pcl-next 房主的房间；pcl-next 的加入端进你的房主的房间）；
5. 在你自己的文档、教程、视频中描述 next 协议，并可引用本仓库的协议文档（注明来源即可）。

上述许可**不需要事先申请**，**不收取任何费用**，但**仅限非商业用途**；任何对外发布的互通实现还必须履行第 4.5 节的开源义务。

### 3.1 什么叫「商业使用」（一律不允许）

只要你的使用行为**直接或间接获得经济利益**，即属于商业使用。包括但不限于：

* 售卖、出租、订阅收费，或把联机 / 互通能力做成**付费版本**、**付费插件**、**会员特权**的功能卖点；
* 在程序内嵌广告、导流、推广位，或以联机功能为入口做付费转化、拉新返利；
* 企业、工作室、团队在**经营性业务**中使用，含为客户代建 / 代管房间、按次或按月收费的联机服务；
* 随硬件捆绑销售、预装并以此获利；
* 以资金、流量、渠道资源换取「优先互通」「官方合作」等排他权益。

允许的非商业场景：个人自用、免费开源项目、公益与教育用途、学习研究、无任何收入的技术演示。

判断有疑问时**按「不允许」处理**。本协议**不授予任何商业许可**，也不存在默认例外；如项目维护者另行出具书面授权，以该授权文件为准。

## 4\. 第三方接入与复刻条款

复刻与互通必须满足以下**五条**义务，缺一即视为违反本协议：

### 4.1 不得冒充官方

* 不得让你的实现被描述为「pcl-next 官方」「PCL Next 内置」「官方认证」，也不得使用 pcl-next 的名称、图标、关于页文案暗示背书关系。
* 你的程序界面、下载页、协议说明中，必须能看出**这是第三方实现**（例如「XX 启动器（兼容 next 协议）」）。
* 允许使用中性表述：`兼容 pcl-next 联机大厅`、`实现 next 协议 v1`、`可与 pcl-next 互通`。

### 4.2 不得绕过准入与身份

* **允许**完整实现准入网关（含 `PCLGATE1` 挑战-应答、ticket 校验、撤销与限速）。
* **禁止**跳过网关校验、伪造/复用他人 ticket、绕过 `proof` 计算、或在房主未启用网关时冒充「已认证」。
* 成员身份字段（`machine\_id`）**必须**为你的程序的真实、稳定标识，不得冒用他人的 `machine\_id`，也不得伪造 `vendor` 冒充 pcl-next 客户端。

### 4.3 不得冒用房间标识

* 房间网络名前缀 `pclnext-` 与房主主机名前缀 `pclnext-mc-server-` 是 next 协议的**互通标识**，允许你的房主端使用它们，**前提**是你的房间确实运行 next 协议 v1、并能被 pcl-next 加入端正常识别与进服。
* 若你的程序同时支持多种大厅（例如自有协议 + next 协议），必须让用户明确知道当前房间用的是哪一种；不得用 `pclnext-` 前缀建一个实际不兼容的房间，把 pcl-next 加入端引到一个打不开的房间。
* 第三方自定义扩展消息**必须**使用非 `c:` 的类型前缀（例如 `z:`、`x:`），不得占用 `c:` 命名空间，避免与将来的协议类型冲突。

### 4.4 不得采集与再分发

* 不得在协议交互中采集超出协议所需的个人信息；`name`、`vendor`、`machine\_id` 只能用于房间内的成员展示与准入，不得上传到你的服务器做画像、广告或转售。
* 不得把通过联机包直传（端口 `25566`）拿到的文件对外再分发、镜像或打包售卖，除非你已获得该内容的权利人许可。
* 不得把房间内获取的日志、报错摘录、成员列表公开展示或用于训练/评测数据集。

### 4.5 互通实现必须开源

**触发条件**：只要你**对外提供**与 next 互通的实现（发布、分发、上架应用商店、提供公开下载，或作为在线服务对外使用），无论免费与否，都触发本节义务。纯私人自用、完全不对外分发的脚本不受本节约束；但一旦分享给别人（哪怕免费、哪怕只是发个压缩包），即触发。

**具体要求**：

1. **源码公开**：放在可自由访问的代码托管平台（GitHub / Gitee / GitLab / 自建公开仓库皆可），任何人无需申请即可浏览与获取；
2. **真开源许可证**：使用被 OSI 认可的开源许可证（如 MIT、Apache-2.0、MPL-2.0、GPL-3.0、AGPL-3.0 等）；**不得**使用「源码可见但禁止修改 / 禁止再分发」的假开源条款，**不得**只提供二进制；
3. **标注到位**：仓库 README 与程序「关于」页都要给出仓库地址与许可证名称；
4. **后续版本同样开源**：协议实现部分（编解码、网关、EasyTier 参数、成员管理）在后续发布中保持开源，不得「首发开源、更新闭源」；
5. **范围边界**：义务只覆盖「与 next 互通所必需的那部分实现」，可以做成独立可编译的库 / 模块单独开源；你程序的其他业务代码（UI、账号、商城等）可以闭源，但不得把协议实现藏进闭源模块来规避本节。

**后果**：不履行本节却对外发布并声称「兼容 next / 与 pcl-next 互通」，属于违约；此时你**不得**使用 `pclnext-` 与 `pclnext-mc-server-` 标识，也不得宣称互通。

## 5\. 禁止行为

在使用联机大厅或实现 next 协议时，禁止：

1. 利用协议发起端口扫描、暴力枚举邀请码、对房主或其他节点实施拒绝服务攻击；
2. 破解、绕过或伪造准入网关、ticket、`proof`，或冒用他人身份进入房间；
3. 未经房主同意，录制、公开或转售房间内的成员信息、聊天、日志与文件；
4. **任何形式的商业使用**（售卖、订阅、广告变现、付费捆绑、经营性代建代管等，见 3.1）；
5. **对外发布与 next 互通的实现却不开源**，或用「源码可见、禁止修改/再分发」的假开源规避 4.5；
6. 以「官方」「认证」「合作」等名义收费、招揽或误导用户；
7. 将本协议用于违反所在地法律法规的活动，或在房间内传播违法内容；
8. 移除、篡改你程序中的来源声明，使其看起来由 pcl-next 发布；
9. 把 next 协议的标识（`pclnext-`、`pclnext-mc-server-`）注册为商标、域名或服务名，妨碍他人正常互通。

## 6\. 数据与隐私

**联机大厅不上传任何数据到中心服务器。** 房间内可见的信息只有：

|信息|谁可见|用途|
|-|-|-|
|昵称（`name`）|同房间的房主与成员|成员列表展示|
|机器标识（`machine\_id`）|房主（以及房主转发展示给成员的列表项）|去重、踢人、发放 ticket|
|客户端标识（`vendor`）|同房间成员|区分客户端来源|
|overlay 内网 IP|房主|排障与审计|
|进服结果与报错摘录（`c:join\_report`）|房主|房主侧提示与排障|
|联机状态（游戏是否运行、实例名、版本、联机包进度）|同房间成员|房间卡片状态|

* 上述数据只在本次房间会话期间保存在内存与本地日志里，退出即失效（日志按本机日志策略保留）。
* 邀请码即房间密钥：分享邀请码等于把房间交给对方，请只发给信任的人。
* 房主启用安全模式（邀请码尾段 `-S`）后，EasyTier 会启用节点间加密握手；但这不改变「房主能看到成员列表」这一事实。

## 7\. 责任边界

1. **房主**负责：房间内容、服务器规则、成员准入（踢人）、自己电脑上的日志与数据留存。
2. **成员**负责：不滥用房间、不传播邀请码、不把房间内文件外传。
3. **pcl-next 项目**负责：协议文档的准确性、官方实现的缺陷修复；**不负责**第三方实现的行为，也不对房间内的内容、可用性、数据丢失作担保。
4. 第三方实现的质量、安全与合规由其作者自行负责；不得以「兼容 pcl-next」为由让本项目承担其责任。

## 8\. 安全与风险提示

* 联机大厅**没有账号体系**，房间安全完全依赖邀请码的保密性与可选的准入网关。
* 邀请码泄露 = 房间暴露；请使用最新版本的邀请码，房间重建后旧码自动失效。
* 「安全模式」只对 pcl-next 自研大厅生效，且**必须双方一致**；第三方实现若未实现 `--secure-mode`，不得宣称支持安全模式房间。
* 准入网关能挡住「拿到 overlay 但没走协议」的裸连接，但**不能**替代 Minecraft 服务器的白名单/正版验证。
* 不要在公网直播、公开论坛直接贴出正在使用的邀请码。

4. 本协议的解释与争议适用中华人民共和国法律；协商不成时，提交项目维护者所在地有管辖权的法院。
