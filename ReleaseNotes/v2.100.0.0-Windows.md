不再是开发过程中的构建序号。VersionCode `5090`（RC 号段 base+90）。

## 从 beta 到 RC 的改动

相对 beta.2，**代码逻辑无改动**——本版只做版本号晋级（版本名 → `2.100.0.0`、VersionCode → `5090`），
把已经在 beta.2 验证过的功能整体推进到正式候选状态。beta.2 引入并已随本版进入 RC 的内容：

- **GitHub 自动更新与渠道晋级**：启动后台静默检查 GitHub Releases，发现更新自动下载、下载完成后
  弹窗确认重启；渠道可选（dev/slush/alpha/beta/rc，默认跟随当前版本）且只升不降。
- **「陆续退出测试版」**：RC 起该选项按规则自动隐藏（`ChannelIsOfficial` 时折叠）——已到正式通道，
  无需再"退出测试版"。
- **关于页**：「项目进度」改为「更新摘要」（dev→beta 路线）+ 作者主页入口。
- **Beta 渠道更新日志修复**：升级提示不再显示"没有更新日志……"。

## 重点验证项（RC 的关键风险）

1. **自动更新全链路**：真实 GitHub API 请求 → 版本判定 → 下载 → 自替换 → 重启，尚无外部验证。
   RC 是这一能力首次进入正式候选，请重点测试。
2. **版本名重置的影响**：版本名从 `2.100.0.7` 变为 `2.100.0.0`（数值变小），请确认升级判定、
   配置文件迁移、更新日志弹窗在"高 VersionCode / 低版本名显示"的组合下行为正确。

## 回滚方案

若 RC 出现 P0：删除 RC tag / Release，回退到 `v2.100.0.7-beta.2-Windows`（commit `84a58f3`）继续修复，
重新走 beta → RC 流程。RC 分支已发布 tag 后禁止 rebase / force-push，回滚通过"回退到 beta 节点另起修复"
而非改写 RC 历史。

## 反馈方式

遇到问题时请附上：复现步骤、日志（`PCL/Log*.txt`）、系统版本与架构（x64 / ARM64）。
若问题出在自动更新，请额外附上 GitHub 检查是否成功、下载是否完成、重启后是否生效。
