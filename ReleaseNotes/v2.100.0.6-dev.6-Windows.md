## 重写

### 1. Phase 4 退出口径裁决 A

《计划-Phase4主体》§4.9 原写「安装编排的 `LoaderBase` 生成改为 C# 输出」。按字面执行会撞架构护栏：
`PCL.Download.csproj` 声明 `<PclIsGuiFree>true</PclIsGuiFree>`，禁止内核引用 WPF / `pcl-next`；
而 `LoaderBase` / `LoaderTask` 定义在 VB 主工程 `ModLoader.vb` 且带 UI 事件，
内核无法产出它，除非先把状态机下沉——那正是排在 Phase 6 之后的 T2 拆壳。

**裁决 A（唯一真源：《计划-Phase4收尾与Phase6下线》§0.1）**：C# 输出**全部编排决策与任务描述符 DTO**；
VB 只做「DTO → `LoaderBase` 树」的**无逻辑装配**，执行 lambda 仍在 VB，`LoaderBase` 公开签名不改。
Phase 4 完成判据改为「**UI 行为不变（含禁用态）、进度 / 取消 / 重试正确，且安装步骤的顺序 / 权重 /
Block / Show / 下载清单与任务描述符全部由 C# 决定**」，装配层不得出现 `If 组件已选 Then …` 形式的业务判定。
口径 B（提前 T2）未采纳。后续不得以「C# 没产出 Loader」为由重开 Phase 4。

### 2. P4-A：编排决策 DTO 全集

| 文件 | 内容 |
|---|---|
| `InstallTaskDescriptor.cs`（新增） | `InstallLoaderKind` / `InstallCancelSemantics` 枚举、`InstallTaskDescriptor` 只读描述符、`InstallTaskDescriptors` 规格工厂、`InstallTaskPlanner.Describe` 装配入口 |
| `InstallPlan.cs` | `InstallPlanStep` 挂装配规格（`Task` / `Inputs` / `Outputs` / `SubSteps` / `DownloadKinds` / `Cancel` / `ReportsProgress` / `SubStepsSource`）；`InstallPlanRequest` 补 `HasMinecraftJson`；`Build` 末尾统一注入规格，**现有 15 个字段语义与所有 Block / 权重布尔式零改动** |
| `InstallDownloadPlan.cs` | 新增 `NetFileDescriptorKind` 13 类；`InstallDownloads` 从 1 个工厂扩到 13 个，把 VB 里散落的 `New FileChecker With {…}` 校验口径收编为可单测的单一真源 |

描述符只含基元 / 字符串 / 集合 / 枚举，不引用 `McInstance` / `MergeJson` / `MyListItem` / `NetFile` / `LoaderBase`。
下载清单的校验口径逐类对齐：原版 json / 资源索引按 JSON 校验；原版 jar `MinSize=1024 + sha1 + size`；
OptiFine 安装 300 KB、另存 64 KB；Forge 带 Hash 而 NeoForge 不带；Fabric API / OptiFabric 带 `SimulateBrowserHeaders=True`。
这些差异写错不会编译报错，只会静默下到错误页。

### 3. P4-B 批次 1：顶层薄装配层

新增 `pcl-next/Modules/Download/LoaderPlanAdapter.vb`（243 行，`Partial Public Module ModDownloadLib` 的一部分，
共享原 Module 的 `Private` 宿主函数），`McInstallLoadersGet` 由 196 行缩到 91 行（−137 / +31）。

- 原 7 处 `If 组件已选 Then` 归零，改为遍历 `InstallTaskPlanner.Describe(Plan)`，`Select Case D.Kind.Value` 分派到 13 个具名 `Assemble*`；
- 名称 / 权重 / Block / Show 各 13 处一律读 DTO；OptiFine 双形态由 `SubStepsSource` 分派，
  「是否记入安装清单」由 `Outputs` 判定，「补全文件」两个副加载器读 `SubSteps`；
- `InstallPlanRequest.HasMinecraftJson` 由 VB 显式传入，C# 据此决定 `Client` 是否插入「获取原版 json 地址」子步骤；
- `McDownloadClientLoader` / `McDownloadForgelikeLoader` / `MergeJson` 等宿主函数与内联 lambda 原样保留。

本批为等价重构，无用户可见行为变化。

## 优化

- **构建号继承修复**：三条独立仓库的 `git` 历史与旧锚点 `85c17f13` 不共祖，
  `Get-BuildSmallVersion.ps1` 曾把编号重算成 `0.0x`。每份仓库根的 `scripts/build-number.base`
  记录本线继承编号（Windows 65），退化分支按「基数 + 自基线以来提交数」计算；
  `prepare-commit-msg` / `post-commit` 钩子同源修复，不再写出 `Build: 0.05`。
- **RID 护栏兼容**：`ProjectReference` 会被 SDK 移除 `RuntimeIdentifier`，
  改由入口工程 `PclRidWriteCache` 把 RID 写入 `obj/pcl-build.rid` 供被引用工程求值期继承；
  入口工程仍强制自带 `-r`，禁止 `any` 占位。
- **更新日志触发时机**：改为「更新后第一次启动」一次（`UpgradeSub` 写 `SystemPendingUpdateLogFrom`、
  `RunCountSub` 呈现并清除），全新安装首启与日常启动不弹。本版补上该设置项的注册，链路才真正可用。
- **发布标签口径**：`Set-VersionInfo.ps1` 的标签正则支持 `-Windows` / `-Linux` / `-Android` 平台后缀，
  后缀不参与版本名 / VersionCode 推导，使 Windows 线可用带平台后缀的 tag 而不破坏 CI 版本推导。
