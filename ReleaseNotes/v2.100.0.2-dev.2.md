- 资源子系统（Mod / 整合包搜索、版本解析、本地扫描）—— 计划中的 Phase 3，尚未开始

- 音乐、皮肤、披风、联机等非下载模块 —— 不在本次重写范围内

## 修复

> 以下缺陷均为**开发与自测过程中发现**的（并非用户在 GitHub 提交的 issue），
> 按《分支与发布规范》§5.4 的要求一并记录。

- **非 dev 渠道全部被编成 dev**：`vbproj` 注入的 `PclChannelConstant` 是裸名
  （`ALPHA` / `RELEASE` / `SLUSH`…），而代码判断的是带 `PCL_CHANNEL_` 前缀的常量，
  二者不匹配——除 dev 之外的所有渠道 `#If` 链全部落到 dev 分支，一旦真的发布 alpha/beta/rc，
  关于页、遥测开关、版本号偏移会全部出错。处置：`PclChannelConstant` 统一改为
  `PCL_CHANNEL_DEV / SLUSH / ALPHA / BETA / RC / SNAPSHOT`，与 `ModBuildChannel.vb` 对齐；
  并以六渠道矩阵构建验证各渠道的常量解析正确。
- **渠道变更后旧程序集不重编**：渠道常量是编译期注入，渠道切换时若命中增量编译，
  旧渠道的程序集会被原样沿用。处置：新增 `PclChannelGuard`，记录构建所用渠道，
  渠道变化时强制清理并重编（构建日志输出 `PclChannelGuard: recorded/current/const/defines`）。
- **代号改名收尾（pc → rc）**：渠道枚举、显示名（「正式版」）、注册表键
  （`SystemHighestRcVersionReg`）与文档引用统一到 `rc`，避免同一代号出现两套叫法。
- **发布输出目录按渠道隔离**：构建产物输出到 `bin-net10/<渠道>/`，不同渠道的产物不再互相覆盖。
- **下载 C# 引擎全源连接挂起时的静默卡死**（随 `v2.100.0.1-dev.1` 标签之后的提交进入本构建，
  真机 NeoForge 26.3.0.99 安装复现，卡在 2%、0 B/s 约 90 秒、日志零输出）：根因为某镜像响应异常时，
  所有源的连接在超时后进入 `OnChunkFailure` 的非禁用路径——该路径既不打日志也不打警告，
  调度器静默换源循环重试，用户视角等于卡死。处置：非禁用路径补 Warn 日志（源 / 失败次数 / 异常）、
  成功开启分块时补日志（对齐 VB 行为）、连接超时的 `OperationCanceledException` 转义为明确的
  `TimeoutException`、`DownloadOptions` 新增 `MinConnectTimeoutMilliseconds`（默认 15000，对齐 VB）；
  并补充回归单测（两源均连接挂起 → 必须超时换源、留痕、最终明确失败）。

## 已知问题

- **本版本是 .NET 10 迁移与 C# 重写过程中的中间产物**，主程序行为与 2.99.0.1 正式版存在差异：
  - 启动器**没有内置的自动更新模块**：上游 PCL 依赖自带的更新服务器，而 pcl-next 没有自己的
    更新源，因此已把更新通道整体下线——「检查更新」改为直接打开本项目的 GitHub Releases 页面，
    升级需手动下载新版本。
  - 资源子系统、下载 UI、整合包与游戏启动等模块仍是 PCL2 的 VB 实现。
  - 整合包导出不再向整合包内塞入「下载来的正式版 PCL」，改为在正式通道下直接复制当前运行的
    启动器本体（dev 通道下则不附带 PCL）。
- 下载服务刚切换到 C# 引擎，仅有单测覆盖，**尚未经过真实网络环境的充分验证**。
  遇到下载异常时请附上 `PCL/Log1.txt` 反馈。
- dev 版与正式版的配置、注册表相互隔离，可与 2.99.0.1 正式版并存；
  建议在升级前备份 `%APPDATA%\.PCL\` 下的配置目录。
- dev 版不上传遥测。
- **构建期仍有大量 CA1416 平台兼容性警告**（数千条，集中在上游 PCL2 遗留代码调用的
  Windows 专有 API 上）：不影响编译产物与运行，但属于 .NET 10 迁移的技术债，
  需在后续 C# 重写中逐项消除。
