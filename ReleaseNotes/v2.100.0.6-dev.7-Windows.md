## 重写

### 1. 迁移方式

以 ICSharpCode.CodeConverter 做**机械转换**，再用 `scripts/Fix-CSharpSemantics.py` 做工序化的语义后处理，
最后逐文件人工审读清偿。转换器把 VB 语法搬到 C# 时，有一批「能编译但语义不同」的陷阱，
这类问题不会报错、只会静默走偏，是本版修复的主要来源（见下节「迁移语义陷阱」）。

### 2. 工程切换

| 项 | dev.6 | dev.7 |
|---|---|---|
| 主工程 | `pcl-next.vbproj`（VB.NET） | `pcl-next.csproj`（C#） |
| 入口 | `PclEntryPoint`（VB `Module`） | `PclEntryPoint`（C# `static class`） |
| 解决方案 | 含 vbproj | `pcl-next.sln` 全部为 `.csproj`（5 个 C# 工程） |
| CI | `pcl-next.vbproj` 路径 | `pcl-next.csproj`；版本名解析改读 `ModBase.cs` |
| 版本信息脚本 | 读写 `ModBase.vb` / `AssemblyInfo.vb` | 读写 `ModBase.cs` / `AssemblyInfo.cs` |

`Directory.Build.props` 的 `PclModBaseFile`、`scripts/Build.ps1` 的主工程与正则、
`scripts/Set-VersionInfo.ps1` 的三处目标文件、三个 workflow 的 publish / 版本解析路径均已同步。

## 修复（迁移引入的缺陷，全部经真机或最小复现工程验证）

### 迁移语义陷阱（编译器不报错，运行期必炸）

| # | 陷阱 | 表现 | 根因 | 处理 |
|---|---|---|---|---|
| 1 | `IsNothing` → `== null` | 启动即 `Stack overflow. Repeated 32143 times: at MyColor.op_Equality` | `MyColor` 重载了 `operator ==`，在运算符实现里写 `a == null` 会再次调用自身，无限递归 | 运算符内一律改 `is null`（引用比较）；`Equals` 改 `obj is MyColor other && this == other`；补 `GetHashCode` |
| 2 | `Handles X.Event` 子句被丢弃 | 顶栏返回 / 关闭 / 最小化 / 音乐 / 下载按钮、皮肤登录页退出、设置页 Java 手动搜索、关于页复制识别码、联机页加入房间、下载页 7 张组件卡的 `Swap` 全部点了没反应 | VB 的 `Handles` 声明即订阅，转换器直接丢掉了这些子句，C# 侧没有任何 `+=` | 逐处补订阅，并按 `ClickEventHandler(object, EventArgs)` 等自定义委托签名精确匹配；另写脚本对全部 `.vb` 的 `Handles A.B` 与 `.cs` 的 `A.B +=` 做全量比对，确认无遗漏 |
| 3 | `Handles Me.Initialized` → 事后 `+=` | 版本选择页**永远停在「正在获取版本列表」**、加载卡片与「无可用版本」卡片**重叠**；下载页进度**一直 0%**；帮助页**整页空白**；左侧文件夹点击不刷新 | WPF 的 `Initialized` 在 `InitializeComponent()` 内部（`EndInit`）就已触发，构造函数里事后订阅永远收不到，`PageLoaderInit` 状态机从未执行 | 8 处改为在构造函数末尾显式调用；`PageLinkMain` / `PageDownloadInstall` 必须放末尾——它们的 loader 字段被转换进了构造函数体，VB 原本是字段初始化器先于 `InitializeComponent` |
| 4 | `char[] + string` | 新建版本文件夹时提示「文件夹名不可包含 **e** 字符」，正常名字 `26.3-Forge_66.1.5` 被拦 | VB 的 `&` 对 `Char()` 有内建转换；C# 的 `+` 退化成 `string.Concat(object, object)`，把数组 `ToString()` 成 `"System.Char[]"`，非法字符集变成 `S y s t e m . C h a r [ ] ! ;` | 三处（文件夹名 / 文件名 / 完整路径校验）改 `new string(Path.GetInvalidFileNameChars()) + "!;"` |
| 5 | `dynamic` 调用 `ref` 参数 | 下载任务**永远卡在加载中**，子任务全停在 `•••`，无异常无日志 | `ShouldStart(ref TIn, …)` 首参是 `ref`，C# 的 dynamic 调用要求显式写 `ref` 且实参必须是变量，否则抛 `RuntimeBinderException`；异常又被工作线程吞掉，`foreach` 在第一个已完成子任务处中断 | 新增 `CallShouldStart` 用 `MethodInfo.Invoke` 调用（`ref` 可回写；`TIn` 为值类型且输入不匹配时用 `Activator.CreateInstance(TIn)` 复刻 VB 的 `Nothing` → 默认值语义）；`Update` 拆 `Update` + `UpdateCore`，外层 try/catch 记日志并 `Failed(ex)`，此类异常不再静默 |
| 6 | 迁移器多插强转 `(dynamic)(T)((object)x)` | 进「任务管理」页必弹 `InvalidCastException`，整页空白（`LoaderCombo<string>` 转 `List<LoaderBase>`） | VB 晚绑定调用 `CType(Loader, Object).GetLoaderList()` 被写成带具体类型的强转 | 按 `IsGenericInstanceOf(Loader, typeof(LoaderCombo<>))` 分派；非 Combo 的 `LoaderTask` 返回自身单元素列表 |
| 7 | `InitializeComponent` 前的字段使用 | 下载页 `PageUnloaded` 抛 `NullReferenceException`（堆栈 :332） | `InitLoader` 在 `InitializeComponent` 之后才赋值，卸载回调可能早于它 | `InitLoader?.Cancel()` |
| 8 | `RightKey` 菜单 `FindName` 取不到控件 | 版本选择页左侧文件夹右键菜单空白 / 抛异常 | VB 原文用 `New MyListItem` 显式构造菜单项，转换后改成 `FindName` 从模板取，模板里根本没有 | 改回显式构造 `NewFolderMenuItem()`，5 个图标常量（重命名 / 打开 / 刷新 / 删除 / 移除）从 VB 原文提取；并补齐 Vanilla 漏 `Delete`、Custom 漏 `Remove` + `Delete` |

## 已知问题

- **最小化 / 还原动画缺失**：主窗口是 `AllowsTransparency="True"` + `WindowStyle="None"` 的分层窗口，
  DWM 对分层窗口不播放最小化 / 还原转场。与 dev.6 逐行 diff 过 `FormMain.xaml`，除 `x:Class` 命名空间外无差异，
  属 WPF 固有限制、非迁移引入。要恢复系统动画需改 `WindowChrome` 非分层窗口（会丢圆角与外部阴影），
  或自写缩放 + 淡出伪动画（DPI / 多屏下易偏移），两条路都要单独立项。
- **`pcl-next.vbproj` 与 123 个 `.vb` 文件仍留在仓库**：不在 `pcl-next.sln` 中，不参与编译，
  但仍是可被直接 `dotnet build` 的工程入口；下个周期清理为「删除 vbproj + 把 .vb 移入 `legacy/`」。
- **六类加载器（Forge / NeoForge / Fabric / Quilt / LiteLoader / OptiFine）仍未逐类真机安装冒烟**：
  dev.4 欠到 dev.5、dev.5 顺延 dev.6、dev.6 又顺延到本版。这是 **alpha 准入的前置**，
  不能用 `pclcli selftest --suite all` 抵扣（该套件只覆盖 CLI 自检）。
- **本版未做完整 GUI 回归**：C# 重写跨越 231 个文件，本版只对「用户实际反馈到的路径」做了真机验证
  （下载 / 安装 / 版本选择 / 任务管理 / 设置 / 帮助页 / 皮肤登录），其余页面与边界场景未逐项回归。
  发现异常请附 `PCL/Log1.txt` 与截图反馈。
- **迁移语义陷阱可能仍有残留**：本版清偿的 8 类陷阱是「已在真机暴露或被脚本扫出」的部分。
  同类风险点（`LCase(Nothing)` → `.Lower()` 抛 NRE、`Nothing == ""` 在 VB 为 True 而 C# 为 False、
  1-based `Strings.Left/Right/Mid`、`Async Sub` → `async void` 的异常边界）已登记清单但**未逐处排查**。
- **大量 CA1416 平台兼容性警告**：net10 迁移技术债，不影响 Windows x64 单平台发布。
- **构建号仅在本仓库内单调**：三条平台仓库各自一份 `scripts/build-number.base`，编号**不可跨仓库比较**。
- 合规门槛维持不变：上游书面答复并留存前，不扩大分发范围、不打平台 tag、不分发非 Windows 制品。
