# pcl-next 2.100.0.7-alpha.1（Windows）

> **内测版（alpha 阶段首版）**。本版标志着 **`slush` 稳定化阶段结束、`alpha` 内测阶段开始**：
> Windows 线在 `slush.1` 完成 VB.NET 源文件全量退出编译链之后，本版继续清理 VB 兼容层残留
> （`dynamic` 晚绑定、`Microsoft.VisualBasic` 转换函数字面量），并修掉 13 项真实缺陷，
> 其中 1 项为**阻塞级**（所有登录方式必失败、无法启动游戏）。
>
> 标签 `v2.100.0.7-alpha.1-Windows`，制品 **Windows / win-x64 + win-arm64**。
> 本版**仅供内测人员与开发者验证使用**，不进任何公开更新通道，不承诺功能完整与配置兼容。
> **配置可能丢失**：alpha 渠道判定为内测线，升级前请自行备份 `PCL` 配置目录。

## 本版本改动

相对上一发布 `v2.100.0.7-slush.1-Windows`：**57 个文件变更，+946 / −267 行**。

### 1. 修复（用户可感知）

| # | 问题 | 现象 | 修复 |
|---|---|---|---|
| 1 | **登录加载器非法强转** | 离线 / 正版 / Nide / Auth **四种登录全部失败**，启动页停在「登录失败」，无法启动游戏 | `Loader.Output` 按实际加载器类型取用，不再把 `LoaderBase` 强转成 `McLoginResult` |
| 2 | 加载失败原因不显示 | 加载失败时看不到错误文本，反而报类型转换异常 | 错误文本分支按 `LoaderBase.Error` 取，不再强转 `Exception` |
| 3 | 打开网页 / 打开目录 / 以管理员重启失效 | 「反馈」「帮助」「打开日志」点了没反应；「以管理员身份重启」静默不提权 | `StartProcess` 按目标类型决定是否走 Shell：URL、目录、非可执行文件、带 `Verb` 一律走 Shell |
| 4 | 滚动惯性动画瞬移 | 低帧率下滚动内容位置突跳 | 惯性动画改由渲染帧驱动，按帧间隔积分位移 |
| 5 | 版本 JSON 循环继承导致静默退出 | 继承关系成环时启动器无提示直接退出（栈溢出） | 继承链加深度护栏（>8 层抛可捕获异常并记录「疑似循环依赖」） |
| 6 | 实例监视器丢失 | 多实例并发刷新时监视器列表被覆盖，状态不更新 | 监视器列表整表替换加锁，状态回调固定取快照 |
| 7 | 音乐列表空引用 | 音乐列表初始化失败后点击下一首报空引用 | 与主列表同等判空，失败时安全返回空 |
| 8 | 图片兜底二次异常 | 内置资源为 `BitmapSource` / `ImageBrush` 时兜底路径抛类型转换异常，真实原因被吞 | 按三种资源类型分别取用，仍无资源才走 1×1 占位并抛原始原因 |
| 9 | 文本出现动画越界 | 回弹缓动下文本截取越界抛下标异常 | 截取长度钳制在 `0..文本长度` |
| 10 | CurseForge 搜索分页空引用 | 分页节点缺失时在空对象上取索引报空引用 | 分页节点判空后再取 |
| 11 | 正版登录证书校验回调失效 | 原网络配置回调在 .NET 10 下从不被触发 | 证书校验迁到 `HttpClientHandler.ServerCertificateCustomValidationCallback` |
| 12 | 网络连接数配置无效 | `ServicePointManager` 在 .NET 10 下对 `HttpClient` 不生效 | 迁到 `HttpClientHandler.MaxConnectionsPerServer` |
| 13 | 反馈流程异常冒泡 | 反馈提交中途异常直接弹到界面 | 补兜底 `catch` + 日志；校验入口统一空串兜底 |

### 2. 重写 / 代码质量（alpha 期主线）

- **去 VB 兼容层字面量**：`Constants.vbCrLf` / `vbLf` / `vbTab` 共 **381 处**替换为 C# 字面量（43 文件，值等价）；
- **字符串切片**：`Strings.Left` / `Strings.Right` 共 **8 处**改为 C# 范围切片；
- **成员隐藏消歧**：`HttpRequestCodeException.StatusCode` 加 `new`，消除继承成员隐藏歧义；
- 新增 `docs/代码质量审计-2026-11-13.md`，登记剩余 `dynamic` 339 处 / `Conversions` 387 处的分批清理计划；
- 新增 `docs/alpha缺陷扫描-2026-11-14.md`，登记本轮 9 项缺陷的现象、根因、修复与未修项。

### 3. 构建 / 发布链修复

- **发布工作流密钥注入步骤仍指向已删除的 `ModSecret.vb`**：`v2.100.0.7-slush.1-Windows`
  的 Release 运行即因此失败（run `43398844717`，第一步 `Cannot find path … ModSecret.vb`）。
  本版改为向唯一编译入口 `ModSecret.cs` 注入，`build.yml` 同一处缺陷一并修复。
- 构建标识新增内容指纹与 UUID，产物可反查构建提交与工作区状态。

### 4. 文档

- 分支命名收敛为 `<代号>-<平台>`；`dev` 改为「不冻结、但禁止发版」；
- 同步产物两棵树、本地目录与渠道对应关系等条目。

## 开发期发现的缺陷

> 本节记录开发与自测过程中由开发者自己发现并修复的缺陷。**其中第 1 项只有在真实运行启动器时才会暴露**：
> 编译 0 错误、静态审查也发现不了，属于「编译通过 ≠ 功能正确」的典型。

| 缺陷 | 触发条件 | 症状 | 根因 | 修复方式 |
|---|---|---|---|---|
| 登录加载器非法强转（**阻塞**） | 任意登录方式（离线 / 正版 / Nide / Auth） | 启动页停在「登录失败」，无法启动游戏；日志 `Unable to cast object of type 'LoaderTask<…>' to type 'McLoginResult'` | VB 原文 `Loader.Output` 是晚绑定；迁移时多插了一层 `(McLoginResult)` 强转，必抛 `InvalidCastException` | 按实际 `LoaderTask<…,McLoginResult>` 类型取 `Output`，未知类型显式报错 |
| 加载失败原因丢失 | 任意页面加载失败 | 看不到错误文本，反被类型转换异常打断 | `((dynamic)(Exception)((object)State)).Error` 把 `ILoadingTrigger` 强转 `Exception` | 改为取 `LoaderBase.Error` |
| `StartProcess` 全部失效 | 打开网页 / 打开目录 / 打开日志 / 以管理员重启 | 前者弹「无法打开网页」，后者静默不提权 | .NET Core 起 `UseShellExecute` 默认 `false`，URL / 目录 / 非 exe 无法由 `CreateProcess` 解析；`Verb` 被忽略 | 在唯一入口按目标类型判定是否走 Shell，`.exe/.com` 保持直接启动 |
| 滚动瞬移 | 低帧率 / 高刷新率差异 | 滚动位置突跳 | 惯性动画按固定时长而非渲染帧推进 | 改为渲染帧驱动、按帧间隔积分 |
| 版本继承成环静默退出 | 版本 JSON 继承链成环 | 启动器无提示直接退出（栈溢出不可捕获） | 逐层递归构造 `McInstance`，无深度护栏 | `[ThreadStatic]` 深度护栏，>8 层抛可捕获异常 |
| 监视器丢失 | 多实例 / 并发状态回调 | 实例状态不刷新 | 监视器列表「读旧表→建新表→写回」非原子 | 加锁串行化整表替换，回调取快照 |
| 音乐空引用 | 音乐列表初始化失败 | 点击下一首报空引用 | `MusicWaitingList` 可能保持为空 | 同等判空，失败时安全返回空 |
| 图片兜底二次异常 | 内置资源类型为 `BitmapSource` / `ImageBrush` | 兜底路径抛类型转换异常，原始原因被吞 | 一律强转 `System.Drawing.Bitmap` | 按三种类型分别取用，仍无资源才占位并抛原始原因 |
| 文本动画越界 | 回弹缓动 | 文本截取抛下标异常 | 进度可越过 0~1，截取长度未钳制 | 钳制到 `0..文本长度` |
| CurseForge 搜索空引用 | 分页节点缺失 | 搜索页报空引用 | 在空对象上取索引 | 分页节点判空后再取 |
| 正版登录证书校验失效 | 正版登录（证书回调场景） | 证书校验回调从不执行 | `ServicePointManager` 回调不被 `HttpClient` 触发 | 迁到 `HttpClientHandler` 回调 |
| 网络连接数配置失效 | 高并发下载 | 连接数配置不生效 | `ServicePointManager` 对 `HttpClient` 无效 | 迁到 `MaxConnectionsPerServer` |
| 反馈流程异常冒泡 | 反馈提交中途失败 | 异常直接弹到界面 | 无兜底 `catch` | 补兜底并记录日志 |

## 已知问题

1. **arm64 未经真机冒烟**：本版 `win-arm64` 制品已完成交叉编译与 PE 头校验（`0xAA64`），
   但**未在 ARM64 真机上运行过**。按《分支与发布规范》§0.4，arm64 未真机冒烟前只应走 `dev` / `slush`；
   本次经用户明确授权（2026-11-14 选择「双 RID 都发」）随 alpha.1 一并发布，**arm64 用户请视作实验性支持**。
2. **玩法全链路未逐项回归**：本版只完成「启动 → 登录 Finished」冒烟，
   下载 / 安装 / 启动游戏 / 整合包四条主链路未逐项手工验证。
3. **去 VB 兼容层未完成**：`dynamic` 339 处、`Conversions` 387 处仍在，运行期类型错误仍可能出现，
   alpha 期将持续清理。
4. **Linux / Android 线未完成迁移**：两条平台线各自仓库仍有 `.vb` 源文件，本版「VB 迁移完成」仅指 Windows。
5. **平台制品未分发**：Linux / Android 制品在上游授权书面答复留存前不对外分发。
6. **alpha 更新通道与正式源隔离**：本版使用独立升级判定键 `SystemHighestAlphaVersionReg`，
   与正式版互不影响；但独立的 alpha 更新通道（自有更新源）尚未搭建，本版不提供自动更新。
7. **构建环境依赖**：`pcl-next.csproj` 的构建信息生成步骤调用 `powershell`（Windows PowerShell 5.1）；
   仅有 `pwsh` 7 的环境该项静默跳过，需手工生成 `obj/<配置>/PclBuildInfo.g.cs` 才能编译。
8. **本地新功能未入库**：毛玻璃、OKLCh、账号列表页等仍在本地分支/暂存目录，后续重新排期，不做跨分支手工拷贝。

## 升级说明

- **从 `slush.1`（`v2.100.0.7-slush.1-Windows`）升级**：`VersionCode` 5010 → 5020，
  高于旧版，可覆盖升级；配置目录结构与设置项均未变化，直接替换 exe 即可。
- **从 `dev.6` / `dev.7` 升级**：同样可覆盖升级；本版无新增设置项，无配置迁移步骤。
- **从旧 VB 版本升级**：不支持。本版已是纯 C# 运行时，VB 时代的运行时依赖与配置不再兼容。
- **渠道隔离**：alpha 为内测通道，升级判定键与正式版完全独立（`SystemHighestAlphaVersionReg`），
  安装 alpha 版**不会影响**同一台机器上的正式版判定；内测结束后可直接覆盖回正式版。
- **备份建议**：alpha 期允许带已知缺陷发布，**升级前请备份 `PCL` 配置目录**（`%APPDATA%\PCL` 或程序同级的 `PCL` 目录）。
- **下载策略开关**：`DownloadPolicy.ini` 为可选部署期开关；文件缺失时程序走内置默认（允许 MC 下载），
  需要禁用 MC 下载时放入同目录并写 `AllowMcDownload=False`。
