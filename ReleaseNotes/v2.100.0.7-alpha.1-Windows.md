# pcl-next 2.100.0.7-alpha.1（Windows 内测版）

这是 alpha 阶段的第一版。从上一个版本 `slush.1` 到现在，做的事只有三件：**修 bug、拆 VB 残留、修发布流水线**。

**这一版没有加任何新功能**（alpha 阶段的规矩是只收缺陷修复和代码质量改造，新功能留在 `dev`）。所以如果你在找"新增了什么"，答案是：没有，只有"哪些原来坏掉的现在好了"。

最值得说的一条：**上一版所有登录方式都是坏的**——离线、正版、Nide、Auth 全部登不进去，停在"登录失败"，游戏根本起不来。这一版修好了。

## 项目现状

Windows 线的 C# 重写已经走完：`pcl-next` 工程里 0 个 `.vb` 文件，C# 工程是唯一的编译入口。

但"重写完"不等于"没问题"。代码虽然换成了 C#，内在还是 VB 的写法——`dynamic` 还有 339 处、`Microsoft.VisualBasic` 的转换函数还有 387 处。这类残留不会在编译时报错，只会在运行时炸，登录那个 bug 就是这么来的。把这块拆干净，是 alpha 阶段的主线工作。

稳定性上，本版做到"编译 0 错误 + 真实启动、登录跑通"，但玩法全链路（下载、安装、启动游戏、整合包）没有逐项回归。这是内测版，请当成"能跑起来、但别指望处处周全"来用。

## 本版本改动

### 修好的 bug：直接让你用不了的

**1. 四种登录方式全部失败（最严重）**

- 你会看到：点登录，等一会儿，提示"登录失败"，游戏列表点不动，启动不了任何版本。
- 不管你选离线、正版、Nide 还是 Auth，结果都一样。
- 日志里是 `Unable to cast object of type 'LoaderTask<...>' to type 'McLoginResult'`。
- 原因：从 VB 迁到 C# 时，这行多写了一个类型强转，把加载器对象当成了登录结果对象，一取就炸。
- 现在：按真实类型取结果，离线 / 正版 / Nide / Auth 都恢复正常。

**2. 打不开网页、打不开文件夹、以管理员重启没反应**

- 你会看到：点"反馈""帮助"没动静；点"打开日志"没动静；点"以管理员身份重启"，程序重开了但还是普通权限。
- 原因：.NET 10 下启动进程的默认方式变了，网址、目录、非 exe 文件交不出去，`runas` 提权参数也被忽略。
- 现在：按目标类型判断，该走系统外壳就走外壳；exe 仍然直接启动。

**3. 加载失败时看不到原因**

- 你会看到：页面加载失败，本来该显示错误信息的地方没有字，反而弹一个类型转换错误。
- 原因和登录那个是同一个毛病，错误对象被强行转成了异常对象。
- 现在：正常显示加载器给出的错误原因。

### 修好的 bug：用的时候会撞上

**4. 滚动内容会突然跳一下**

低帧率或者系统负载高的时候，滚动列表里的内容会"瞬移"。惯性滚动改成由渲染帧驱动、按真实帧间隔算位移，不再按固定时长硬推。

**5. 版本继承关系成环时，启动器闪退且没有提示**

某些版本 JSON 的继承链互相指（A 继承 B、B 又继承 A），旧代码会一层层递归构造，最后栈溢出——这种崩溃抓不住，进程直接没了。现在加了深度护栏，超过 8 层就报一个能捕获的错误，提示"版本继承层级过深，疑似存在循环依赖"。

**6. 多实例刷新时，监视器会丢**

同时刷新多个版本实例时，监视器列表会被覆盖，界面上的状态就不更新了。改成加锁整表替换，状态回调统一取快照。

**7. 音乐列表加载失败后，点下一首报空引用**

列表初始化失败时，点"下一首"直接报错。现在跟主列表一样判空，失败就安静地不播。

**8. 图片加载失败时，回退逻辑自己又炸一次**

内置资源是 `BitmapSource` 或 `ImageBrush` 的时候，兜底代码硬转成 `System.Drawing.Bitmap`，又抛一次异常，真正的原因反而被盖住了。现在按三种类型分别处理，实在没有资源才用占位图并抛出原始原因。

**9. 文本出现动画偶尔下标越界**

回弹缓动会让进度超过 0~1，取子串时越界。现在把长度钳在 `0..文本长度` 之间。

**10. CurseForge 搜索分页缺失时报空引用**

返回里没有分页节点时，旧代码在空对象上取索引。现在先判空再取。

**11. 正版登录的证书校验回调从来没执行过**

老写法用的 `ServicePointManager` 回调，在 .NET 10 的 `HttpClient` 下根本不会触发。迁到 `HttpClientHandler` 的回调。

**12. 网络连接数配置不起作用**

同样是 `ServicePointManager` 的问题，现在配到 `HttpClientHandler.MaxConnectionsPerServer`（10000）。

**13. 反馈提交中途出异常会直接弹到界面**

现在补了兜底和日志；输入校验入口也统一把空值当空串处理。

### 新增功能

**没有。** 这一版不加任何功能。

毛玻璃卡片、OKLCh 深色配色、账号列表页、高级设置页、颜色编辑器都还在 `dev` 线的本地分支/暂存目录里，等 `rc` 之后再按代号阶梯重新排期——不会通过跨分支手工拷贝的方式混进稳定版。

### 内部重构（你感知不到，但影响后面的稳定性）

- `Constants.vbCrLf` / `vbLf` / `vbTab` 共 **381 处**换成 C# 字面量（43 个文件，值完全等价）；
- `Strings.Left` / `Strings.Right` 共 **8 处**换成 C# 范围切片；
- `HttpRequestCodeException.StatusCode` 补 `new`，消除继承成员隐藏的歧义；
- 新增两份文档：`docs/代码质量审计-2026-11-13.md`（登记剩下 `dynamic` / `Conversions` 的分批清理计划）、`docs/alpha缺陷扫描-2026-11-14.md`（本轮 9 项缺陷的现象、根因与未修清单）。

### 发布流水线修复

- **发布工作流一直指向已删除的 `ModSecret.vb`**：`slush.1` 那次 Release 跑到第一步就失败（run `43398844717`），就是因为这一步。现在改成给 `ModSecret.cs` 注入，`build.yml` 同一处一起修了。
- **ARM64 制品其实是 x64**：双 RID 发布时两个架构共用了同一份中间产物，ARM64 直接复用了 x64 的已编译镜像，产物 PE 头仍然是 `0x8664`。现在按 RID 隔离中间目录，重编后是 `0xAA64`，CI 侧也加了机械校验。

## 开发期发现的缺陷

上面 13 条全是开发和自测时发现的，没有一条来自 GitHub issue。其中登录那条特别值得说一句：**它是编译通过、静态审查也发现不了的**。

第一版改完之后，构建 0 错误，警告也没增多，看上去一切正常。真正跑起来才发现登录必失败——因为那个类型强转只在运行期才炸。所以这一版的验证不是"编过了就算"，而是把程序真的启动、走一遍登录，再翻日志确认到 `登录 状态改变：Finished`、没有一条 E 级记录。同理，`StartProcess` 那三条失效也是拿 PowerShell 实际调 `Process.Start` 复现出来的，不是猜的。

## 已知问题

1. **ARM64 没有真机验证**。ARM64 包能编出来、PE 头也对（`0xAA64`），但没有在 ARM64 设备上真正跑过。按规范这类包本来只能走 `dev` / `slush`，这次经你确认后随 alpha.1 一起发了——**ARM64 用户请当实验性支持看待**。
2. **玩法全链路没逐项回归**。只验证了"启动 → 登录完成"，下载、安装、启动游戏、整合包四条主链路没有一条一条手工过。
3. **去 VB 兼容层还没做完**。`dynamic` 339 处、`Conversions` 387 处仍在，运行期类型错误还有可能出现。
4. **Linux / Android 没跟上**。两条平台线的仓库里还有 `.vb` 源文件，本版"迁移完成"只对 Windows 成立。
5. **非 Windows 制品不对外分发**。等上游作者的书面答复留存之后再谈。
6. **没有自动更新**。alpha 走独立判定键（`SystemHighestAlphaVersionReg`），不会影响同机的正式版；但 alpha 自己的更新通道还没搭，本版只能手动下载覆盖。
7. **构建环境仍依赖 Windows PowerShell 5.1**。构建信息生成那一步用的是 `powershell`，只有 `pwsh` 7 的机器会静默跳过，需要手工生成 `obj/<配置>/PclBuildInfo.g.cs` 才能编。
8. **本地新功能仍未入库**。原因见上文，不做跨分支拷贝。

## 升级说明

- **从 `slush.1` 或 `dev.6` / `dev.7` 升级**：直接替换 exe 就行。VersionCode 从 5010 升到 5020，配置目录结构、设置项都没变，不需要迁移。
- **从早期 VB 版本升级**：不行。现在是纯 C# 运行时，VB 时代那套依赖和配置不认了。
- **和正式版的关系**：alpha 的升级判定键是独立的，装了 alpha 不影响同机正式版的版本判定；内测结束后直接覆盖回正式版即可。
- **建议先备份**。alpha 允许带已知缺陷发布，升级前把 `PCL` 配置目录（`%APPDATA%\PCL` 或程序同级 `PCL`）复制一份。
- **想关掉 MC 下载**：把 `DownloadPolicy.ini` 放到 exe 同目录，写 `AllowMcDownload=False`。不放这个文件也能正常运行，走内置默认（允许下载）。
