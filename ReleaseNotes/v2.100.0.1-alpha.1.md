# pcl-next 2.100.0.1-alpha.1

> **内测版**。按《分支与发布规范》§1.3，内测版仅面向少量受邀用户，允许带已知缺陷发布，
> **可能存在已知缺陷，甚至会导致配置丢失或游戏崩溃**，请务必先备份 PCL 的配置与整合包。

## 新增

- **渠道（发布通道）体系**：按《分支与发布规范》区分 `dev` / `slush` / `alpha` / `beta` / `pc` / `snapshot`
  六种渠道。渠道代号、显示名、版本号段、遥测策略、提示文案与制品名统一由 `ModBuildChannel` 提供，
  编译期常量由 CI 按分支注入，不再由「构建配置」决定渠道。
- **版本号按号段表分配**：`base = 5000 + 100 × 周期序号`，`alpha = base+0…39`、`beta = base+40…69`、
  `PC = base+70…79`、`SP = base+80…99`，开发 / 收敛版取 `base-1`，保证全局单调递增。
- **MC 下载功能恢复**：开关由编译期常量下移为部署期配置，支持环境变量 `PCL_ALLOW_MC_DOWNLOAD`
  与启动器同级的 `DownloadPolicy.ini`，并随产物分发配置样例。
- 渠道隔离的「历史最高版本号」记录项，开发 / 收敛、内测、公测、正式四类各记各的，
  避免不同渠道的版本号互相污染升级判定。

## 重写

- 主程序由 .NET Framework 迁移到 **.NET 10**（`net10.0-windows`），改为 SDK 风格工程，
  发布形态为 **自包含单文件**（`pcl-next.exe`），目标机无需安装任何 .NET 运行时。
- 第三方依赖统一改走 NuGet（CacheCow、NAudio、Imazen.WebP、ThrottleDebounce、Newtonsoft.Json），
  移除原先「内嵌 DLL + `AssemblyResolve`」的动态加载机制。

## 修复

- GBK / GB2312 等代码页缺失导致社区资源（Mod 加载器）加载失败：启动时注册 `CodePagesEncodingProvider`。
- 旧版 HTTP 缓存格式不兼容导致启动报错：缓存目录切换到 `Cache/HttpV2`，
  并新增缓存装饰器，读到损坏条目时删除并按未命中处理。

## 已知问题

- 本版本为 **.NET 10 重写后的首个内测构建**，主程序行为与 2.99.0.1 正式版存在差异，
  已知差异包括：启动器自身不再包含更新通道（`UpdateCheckByButton` 为占位实现），
  整合包导出仍沿用旧版「下载正式版 PCL」的逻辑。
- 首次运行内测版会弹出「内测版使用说明」，请注意其中关于配置丢失与崩溃的提示。
- 本版本尚未接入独立的内测更新通道，升级需手动下载新版本。

## 升级说明

- 内测版与正式版的配置、注册表相互隔离，可与 2.99.0.1 正式版并存。
- 建议在升级前备份 `%APPDATA%\.PCL\` 下的配置目录。
